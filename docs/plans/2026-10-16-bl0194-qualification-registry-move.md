## 0. Thesis
llm-playground model intake is where a qualification exam is administered. Intake calls autopilot `scripts/engine-qualify.sh` under the P5 headless contract and commits the schema-2 record itself. llm-playground is the only registry of exam records. The authoritative store is, per workspace, `benchmarks/qualification/<ws>/<record>.json` (one file per record) and `benchmarks/qualification/<ws>/strikes.jsonl`. autopilot keeps local evidence for an exam this install administered, local strikes, a user pin, and a cache of the feed. The P3 outbox and its transport exist and default to off. The historical split (autopilot scorecard plus a hand import, a feed with no speed or cost, a stale cache fetched 2026-09-03) is what P1–P4a already replaced on the publish side; this revision replaces who administers the exam and how a feed row is trusted. Shipped consult result A2/B1 remains: one registry, snapshot-built defaults. C1's old reading (metrics never affect admission) does not.

## 1. KRs
- KR1 one authoritative record store. A headless `engine-qualify` (P5) writes only `--store` and `--raw-dir` and does not touch `~/.autopilot`. An exam administered on an autopilot host still keeps its local evidence on that host. The registry copy is llm-playground's commit.
- KR2 feed carries pass rate, solved/hour and cost (null when unknown) per seat x role.
- KR3 no result or strike lost or duplicated under network, push or CI failure (fault tests).
- KR4 with `qualification_feed.trust=off`, admission is identical to having no feed (same path, same admitted set, same ordering hash). With `auto`, only a feed that passed the gate is used. With `confirm`, a row is used only after that gate and a matching confirmation line (section 2). Both stay under the three invariants: the feed never overwrites local evidence, a local strike always wins and the feed cannot lift it, and a user pin always wins. Confirmation cannot bypass the gate or those invariants.

## 2. Constraints (verbatim into every dispatch)
- ADR-0001: disclosure, not attestation. No signatures, hash chains, witness receipts; `digest` stays a cache key.
- Admission reads four inputs, in this order: a user pin, local strike records, local evidence, then the feed under `qualification_feed.trust`. Local evidence means a result this install administered itself. It is usable immediately, including when the optional outbox is on and the row is still unacked. The feed never overwrites local evidence, never lifts a local strike, and never beats a pin.
- `qualification_feed.trust` defaults to `auto`. `auto`: a qualification result that passed the gate is used for admission, with no adopt step. `confirm`: no adopt command. The prompt surface is the existing owner pending-decision panel (`scripts/open-decision.js`). When new feed rows appear, open one card for the whole batch of new rows, not one card per row. When the owner answers on the panel, write a confirmation record to `~/.autopilot/qualification-feeds/confirmations.jsonl`. Each line holds `record_id`, seat (`engine`, `runner`, `role`, `effort`), content digest (sha256 of that record's normalized bytes), `confirmed_at`, and the card id. With nobody answering, including a headless-only session, unconfirmed rows are not adopted and the feed behaves as if those rows were absent. Re-confirmation is required when the same `record_id` has a changed content digest, or when a new `record_id` appears. A renew with unchanged content needs no re-confirmation. One card covers the batch; one confirmation line is written per `record_id` and content digest. After confirmation, every admission still passes the gate and the three invariants (local evidence is never overwritten, a local strike always wins and the feed cannot lift it, a user pin always wins); confirmation cannot bypass them. `off`: the same admission path as no feed, so the admitted set and the ordering hash are identical. Speed and cost metrics still only order seats; they do not admit or deny. The old C1 reading (a feed qualification never admits) is withdrawn.
- The gate reuses the shipped preflight, and any single failing step rejects the whole document. Strict JSON, document shape, and the digest come from `scripts/lib/qualification-feed.js` `parseFeed(body, origin, bytes)`, which runs `preflightJsonSource` (imported from `scripts/validate-json-schema.js`), then `JSON.parse`, checks the document shape, and computes the digest. `readFeedSource` and `loadFeed` in the same file do the strict UTF-8 decode, refuse a symlink, and enforce the size cap `MAX_FEED_BYTES`. `parseFeed` does not validate against a schema and does not validate qualification entries. There are two documents. (a) The feed document read by `parseFeed` and `loadFeed`. Its legacy adopt path validates the artifact against `schemas/official-qualification-defaults.schema.json` through `scripts/validate-json-schema.js` (`scripts/adopt-qualification-defaults.js`). (b) The sibling metrics document `qualification-metrics.json`, schema id `model-dyno.qualification-metrics.v2`. P2 and the admission ordering read document (b). `admissionView` in `scripts/lib/qualification-metrics.js` supplies the qualification entries admission uses from that document's `seat_metrics` where `kind` is `qualification` (a `qualified` status is a feed claim). P6 admission reads document (b), not the feed document. Before any row is used, the whole metrics document goes through parseFeed-level strict JSON (`preflightJsonSource`, then `JSON.parse`) and then `validateMetrics(raw, {semantic: true})`. `validateMetrics` does that strict parse, validates the document against `schemas/qualification-feed-v2.schema.json`, and runs the semantic checks `checkEntries`, `checkBenchmark` (called from `checkEntries` for a `benchmark_observation`), and `checkStrikes`. Any record objects go through `validateRecord(raw, {semantic})`, which calls `checkRecordSemantics(rec)` and validates a schema-2 record against `schemas/qualification-record.schema.json`. A single failing entry rejects the whole document. There is no partial use. Feed freshness today is only `checkSnapshotAge` in `scripts/build-qualification-defaults.js` (a release-time gate on the recipe's `snapshot.generated_at`, default 30 days, CLI-local, not exported) and the 7-day warn in `scripts/lib/qualification-metrics.js` (`DEFAULT_MAX_AGE_S`, `describeAges`). P6 extracts the 30-day rule out of `checkSnapshotAge` into a shared exported function (in `scripts/lib/qualification-feed.js`) that takes `generated_at`, now, and max days, so `build-qualification-defaults.js` and the P6 admission path call the same function. The extraction boundary is the pure age comparison: a missing or malformed `generated_at` fails, a future `generated_at` fails, and an age older than max days fails. Recipe reading and process exit stay in `build-qualification-defaults.js`. The expected digest is the recorded content-addressed cache identity: the cache key, the directory name under the cache, and the digest recorded in the current manifest. On every admission read, recompute the sha256 of the cached wire bytes and compare it with that recorded identity. If they are unequal, reject the whole document and report loudly (non-zero status, a visible error line). This is different from computing a fresh identity at first download: at first download the digest is computed and recorded, and there is nothing to compare against; on later reads the recompute is compared against the recorded value. The producer's self-advertised digest is informational only and is never that expected value; `parseFeed` reports `advertised_digest` and never trusts it. The wire digest detects only alteration of the cached copy, and only by comparison with the previously recorded expected digest. It does not authenticate the publisher and does not stop TLS or DNS substitution. Transport protection relies on the existing HTTPS boundary. A successful transport substitution has the same risk as a compromised publisher: `auto` accepts that risk, limited by the local invariants (local evidence is never overwritten, a local strike always wins, a user pin always wins) and by `confirm` or `off`. Any other gate failure is also treated as no feed and is reported loudly. The gate covers malformed documents, an unsupported schema id or version, a single bad entry, a stale `generated_at`, and a cached copy whose bytes no longer match the recorded digest. It does not decide whether a fresh, well-formed document is true; that residual is the threat model in section 8. The three invariants cover overwriting local state.
- Unknown is null, never 0. Wire numbers are integers: enforced by `type: integer` in the shared schema (current `validate-json-schema.js` accepts a lossless non-integer literal unless the schema says integer).
- Every new check ships a negative control, red before green.
- No dual-read shims (owner rule). Compatibility = v2 is a superset of v1.

## 3. Shared spec (single source)
`schemas/qualification-feed-v2.schema.json` in llm-playground is the only spec. autopilot vendors a byte-identical copy at `schemas/qualification-feed-v2.schema.json` (parity test fails on any diff). Validators: llm-playground `scripts/eval/check_qualification_feed.py` (stdlib; supports type/required/enum/pattern/additionalProperties/minimum/oneOf, tested in `scripts/eval/test_qualification_feed.py`); autopilot `validate-json-schema.js`. Both run the same fixture set in `benchmarks/qualification/fixtures/` (copied into autopilot `hooks/tests/fixtures/`).

### 3.1 Feed document (v2 is a superset of v1)
Discriminator: string `schema` = `model-dyno.qualification-feed.v2` (v1 name pattern kept; the only version key; `schema_version` is not used). All v1 top-level keys, including v1 `strikes[]` with its entry shape, stay byte-unchanged. New top-level: `generated_at` (UTC `...Z`), `producer` (string), `source_revision` (git sha), `seat_metrics[]`, `strike_events[]`. Compatibility test: the current `parseFeed` reads a v2 fixture, results for v1 fields byte-identical.

### 3.2 `seat_metrics[]` entry (additionalProperties false; `kind` discriminates)
- `entry_id` string, sha256 hex of canonical JSON (sorted keys, no whitespace) of [`seat`, `kind`, `instrument_id`, `window_end`]; `window_end` (UTC `...Z`) is a required top-level field of every entry.
- `seat` {engine, model, model_version, runner, role, effort}: strings. No seat hash is published (consumers recompute).
- `kind`: `qualification` or `benchmark_observation`. Required block per kind: qualification => `qualification` only; benchmark_observation => `benchmark` + `speed` + `cost` + `sampling`. Any other block present is invalid (fixture mixing blocks must fail).
- `instrument_id`, `instrument_version`: strings.
- `qualification` {status: qualified|failed|provisional, corpus_version, prompt_config_hash, administered_at, record_id, record_id_basis, supersedes: record_id or null}; `expires` advisory.
- `benchmark` {n_tasks (per trial), n_trials (repeated runs of the task set), n_attempts (every execution incl. retries, >= n_tasks*n_trials), n_pass and n_timeout (attempts), pass_rate_permille = round-half-up(1000*n_pass/n_attempts), ci_method `wilson`, ci_level_permille 950, ci_low_permille, ci_high_permille}. Every ratio is null when its denominator is 0.
- `speed` {solved_per_hour_milli = round-half-up(n_pass x 3.6e6 / wall_s_total), wall_s_total = summed wall seconds of ALL attempts; tasks_per_hour_milli = same with completed attempts; median_wall_ms (per task, integer ms); concurrency; speed_basis = `window_start..window_end` text}. Zero denominator => null.
- `cost` {usd_per_solved_micro, usd_per_task_micro, cost_total_micro, cost_coverage_permille (attempts with known cost), cost_basis billed|estimated|subscription|unknown, pricing_version}. Unknown => null with coverage 0; subscription => null; null sorts last.
- `sampling` {window_start, low_n (n_trials < 5)}. Units: `_permille` 1/1000, `_milli` 1/1000 unit, `_micro` 1e-6 USD, `_ms` ms; every derived integer rounds half-up.
- `join` {board_cell, board_join mapped|unmapped, identity_map_version}: unmapped rows are shown, never ranked. No map hash is published.
- `origin_host_class` only (`local-gpu`|`cloud-api`). `evidence_ref`: relative path inside the registry repo, never a URL.
Example (benchmark_observation, one entry) is `fixtures/seat-metrics-benchmark.valid.json`, written in P1 before the producer code.

### 3.3 `strikes[]`
`strike_events[]` entry (v1 `strikes[]` untouched) {strike_id, strike_seq (integer, assigned by the registry at commit, monotonic per seat; the sender never supplies it), seat, effort or null, reason, lifted_by: strike_id string or null}. Disclosure only: for autopilot it is report and cross-host reference data. No trust mode writes, overwrites, or lifts a local strike; `lifted_by` is informational. A feed that names a lift of a local strike is rejected for that strike. Local evidence wins over any feed row for the same administration.

### 3.4 Keys
- `record_id` = sha256 of canonical JSON of [`producer`, `transcript_hash`, `seat` (6 fields), `corpus_version`, `administered_at`]; `record_id_basis` = `v1:` + that field list. `engine-qualify`, the importer and the ingest share one implementation per language and a cross-language parity fixture; the importer must produce the same id for the same administration (P1 test).
- `strike_id` = sha256 of canonical JSON of [`seat`, `effort`, `reason`, `administered_at` of the failing record, that `record_id`].
- Same id with different payload bytes = conflict: rejected loudly, never merged.

## 4. Write path
Primary path, the one intake uses: llm-playground calls `scripts/engine-qualify.sh <role>` with `--seat-file`, `--store`, `--raw-dir`, and `--emit-record`. `scripts/engine-qualify.sh` execs `scripts/engine-qualify.js`. The process writes only those two directories and does not touch `~/.autopilot`. There is no bot PR on this path.

Exit codes, documented in the HELP text of `scripts/engine-qualify.js`. No two outcomes share a code. Existing codes stay: 0 means qualification passed; 1 means qualification failed, which is `process.exit(runResult.qualified ? 0 : 1)` and today also covers a `no_verdict` administration because that row has status `no_verdict` and `qualified` false; 2 means a usage or precondition error. New codes for the headless contract: 3 means `no_verdict` or an infrastructure failure (the exam could not reach a verdict, and must be distinguished from 1, which means a real failed exam); 4 means the seat file is invalid (missing, unreadable, or fails the seat schema); usage errors that are not about the seat file stay 2; 5 means the emitted record failed schema or semantic validation (`validateRecord` / `checkRecordSemantics`). Existing callers keep working because 0, 1, and 2 are unchanged. The old exit 1 of a `no_verdict` run changes to 3 only when `--emit-record` or `--seat-file` is used, so the existing behavior is untouched without those flags.

Seat file: P5 creates `schemas/qualification-seat.schema.json`. Its fields follow the strict identity token rule `TOKEN = ^[A-Za-z0-9._:-]{1,128}$` in `scripts/engine-qualify.js` for `engine`, `model`, `model_version`, `runner`, `role`, `effort`, `prompt_config_hash`, and `corpus_version` (the same eight fields as the schema-2 record's `seat6_record` definition in `schemas/qualification-record.schema.json`). `additionalProperties` is false. Engine and model ids keep the engine-token spelling the existing flags accept.

Output record: `--emit-record` prints one schema-2 record accepted by `scripts/lib/qualification-metrics.js` `validateRecord(raw, {semantic})` and `checkRecordSemantics(rec)`, and by llm-playground `scripts/eval/ingest-qualification-record.py --kind record` (idempotent by `record_id`; exit 0 created or noop, 3 rejected, 2 usage). Required fields of a schema-2 record (`oneOf[1]` in `schemas/qualification-record.schema.json`) are `schema`, `record_id`, `record_id_basis`, `source`, `seat`, `verdict`, `raw`, `imported_at`, `producer`, `transcript_hash`, `administered_at`, and `origin_host_class`. Identity rule: `record_id` is the sha256 over the canonical JSON of [`producer`, `transcript_hash`, seat6(`seat`), `corpus_version`, `administered_at`] (`recordIdV1` in `scripts/lib/qualification-metrics.js`; seat6 is `engine`, `model`, `model_version`, `runner`, `role`, `effort`). `checkRecordSemantics` rejects `RECORD_ID_MISMATCH` otherwise. The ingest also refuses a second record under a different `record_id` with the same secondary key (`seat`, `corpus_version`, `administered_at`) as `SECONDARY_KEY_COLLISION`. llm-playground imports the printed record with that ingest and commits the file itself.

Write boundary: the headless exam runs with a temporary `HOME`. A filesystem snapshot (path, size, mtime, and content hash of every file) is taken before and after. The test fails red on any change outside `--store` and `--raw-dir`, including an outbox enqueue under `~/.autopilot/qualification-outbox`. Its negative control deliberately writes one stray file, and separately an outbox line, and is shown red before the confined run is green.

Optional path, default off: an exam that was administered on an autopilot host, not by intake. The host keeps local evidence. llm-playground's importer pulls that host's store and commits the record itself. The P3 outbox (`~/.autopilot/qualification-outbox/outbox.jsonl`, append-only, one line per append under `flock`, events `enqueued|sent|acked|retired`) and its flush transport stay available only when that host enables them. Transport is retained for a host that cannot be pulled. It is not how intake writes the registry. A feed refresh never alters a local strike, acked or not. Failpoints `AUTOPILOT_OUTBOX_FAILPOINT=<after-enqueue|after-send|before-ack|after-ack>` cover the optional path only.

## 7. Disclosure gate
CI scans the NEW fields (`seat_metrics`, `strike_events`, metrics file) plus an explicit allowlist: v1 `feed.evidence_url` is allowed only as a pinned autopilot blob URL matching `^https://github\.com/cookys/autopilot/blob/[0-9a-f]{40}/` (commit-pinned, 40 hex chars, producer pin `EVIDENCE_PIN_SHA` 4365285010b2e21e1920be171dee92fbe5165958), path percent-decoded repeatedly and then rejected if it has a `.` or `..` segment; nothing else with a scheme. Blocked in scanned fields: RFC1918 and public IPs, URLs, `.local`/`.internal`/`.lan` hosts, `/home/`, `/srv/`, `Bearer`/`sk-`/token-like strings, bot branch names, and for keys `signature`, `hmac`, `prev_hash`, `witness`, `attestation`, `merkle`. Each class (hostname, IP, URL outside allowlist, home path, endpoint pattern, token string, trust key) has its own committed fixture that must fail red before green; a v1 `evidence_url` fixture must pass.

## 8. Risks
Optional outbox left enabled on a host that intake does not use (default off; status shows it). Infrastructure leak (section 7). A gate-failed feed treated as authority (P6 negative: admission unchanged, loud report). Strike divergence (registry assigns seq; no trust mode lifts a local strike). Stale cache (ages, 30-day gate). The 14 raw seat conflicts if an importer rewrite lands before the owner picks an option (Revision 2026-10-19).

Under the default `auto` mode, a compromised publisher can use fresh, well-formed data to make a seat with no local evidence pass admission. `auto` accepts this risk deliberately. The owner can choose `confirm` or `off`. The gate covers malformed documents, an unsupported schema, a single bad entry, a stale document, and a cached copy that no longer matches the recorded digest. It does not authenticate the publisher and does not stop TLS or DNS substitution. The invariants cover overwriting local state (local evidence is never overwritten, a local strike always wins and the feed cannot lift it, a user pin always wins). Confirmation does not add a fourth bypass.

Threats and the mechanism that limits each:

1. A forged feed qualifying an attacker-chosen seat is limited only by the invariants and by `confirm` or `off`.
2. A stolen producer sending a plausible v2 is limited the same way: only by the invariants and by `confirm` or `off`.
3. TLS or DNS substitution is not stopped by the wire digest or by schema validation. The wire digest detects only alteration of the cached copy, and only by comparison with the previously recorded expected digest. It does not authenticate the publisher. Transport protection relies on the existing HTTPS boundary. A successful transport substitution has the same risk as a compromised publisher: `auto` accepts it, limited by the local invariants (local evidence is never overwritten, a local strike always wins, a user pin always wins) and by `confirm` or `off`.
4. A `generated_at` that is backdated, or a stale replay, is limited by the 30-day freshness check.
5. Schema-correct but semantically wrong data is limited by strict JSON, `checkRecordSemantics`, and the disclosure gate (section 7).

## 9. Out of scope / open
Metrics as an admit/deny gate (speed and cost stay ordering-only), exam content, auto-refresh timers, signatures, seat renames, dashboard UI. Transport is not open: it stays, optional, default off (section 4). TTL 7 d, expiry label 90 d, and snapshot 30 d stay owner-tunable. The 14 raw conflicts are an owner decision and are not taken here.
