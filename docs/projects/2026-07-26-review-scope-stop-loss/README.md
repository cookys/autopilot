# Review Scope Stop-Loss

## Project Goal

> **Final goal**: prevent implementation review from silently changing the task while
> preserving high-severity blockers that are actually relevant.
>
> **Success criteria**: three explicit finding dispositions; only `must-fix-now` enters
> repair; deterministic subsystem/diff-growth stop-loss; focused negative controls and
> existing review suites pass.
>
> **Scope boundary**: implementation-review adjudication and repair-loop scope control
> only. No reviewer-roster, severity, plan-review, or consuming-project product changes.

## Decision Log

- Severity and relevance are orthogonal. Union-on-verified findings remains the severity
  aggregation rule, but it cannot grant authority to widen the task.
- Uncertain relevance halts for adjudication; it never defaults to “fix it”.
- Scope-growth accounting uses the full task-base diff each round. The frozen contract
  has explicit allowed prefixes/new files plus ratio and absolute churn caps; crossing
  either cap stops automatic repair and cannot be reset inside the same loop.
