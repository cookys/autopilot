# Skill metadata portability and documentation capacity rubric

## R1 Platform evidence is real and residue-free

Installed Claude Code and Codex load disposable unknown-frontmatter plugins through supported surfaces;
receipts bind versions, commands, exits, discovery, warnings, and teardown without persistent user-state
changes. Each attempt uses a caller-owned mode-0700 temporary directory, same-invocation task-specific
config/cache roots, before/after inventories, raw-log digests, and an exact residue-path receipt. `--check`
passes every truthful residue-free `pass|fail|inconclusive` terminal and fails evidence defects; it does
not coerce an honest negative result into a failing workflow.

## R2 Tier migration is conjunctive

Canonical `tier:` metadata changes only after both platforms pass. A fail or inconclusive probe leaves
skill frontmatter unchanged and retains the backlog entry.

## R3 Tier metadata and mirrors are exact

On a dual pass, every canonical skill has exactly one `core`, `delegation`, or `pioneer` tier derived
from the published grouping, generated Codex mirrors are byte-equivalent, and routing descriptions/body
semantics do not change.

## R4 OpenCode recovery is reported honestly

The observed nondeterministic 0/1/0 discovery evidence is durable and check 16 remains advisory. No
retry-success or partial corpus is promoted into a hard-gate claim.

## R5 Documentation capacity and links are clean

The mandatory probe inventory expansion restores at least 1,000 bytes of post-change `CLAUDE.md`
headroom without losing script membership/call pointers, the harness-maintenance Available Scripts row
and Codex mirror agree, and the archived residual-spike link passes the deterministic doc gate.

## R6 Verification and review are complete

Platform/probe controls, structural validation, doc drift, portability meta-smoke, sync/mirror checks,
the complete suite, and one whole-diff independent panel pass with no unresolved Critical or Major
finding.

## R7 Execution is bounded and lineage-preserving

The node uses its declared dependency, exact acceptance commands, gate-attempt and repair-generation
budgets, and resource reservation. A failed probe or verification is repaired in the same node and same
foreman/implementer transcript; it never creates a replacement graph, branch lineage, ticket, or model
seat. Its substantive outputs are limited to the probe/test, mandatory inventory/headroom and
harness-maintenance table/mirror edits, conditional tier metadata/mirrors, receipt, and exact stale-link
correction. Among shared lifecycle documents only that link may change; semantic shared closeout stays
with the downstream review-path node.
