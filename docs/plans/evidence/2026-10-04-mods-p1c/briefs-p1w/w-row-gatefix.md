## Depth-0 rulings (binding)
1. **進行中 while the session works** (capture `df-running-2`: task in_progress, Claude mid-turn, no dispatch → band said 待命). 待命 means the turn ENDED and nothing else is going on. Rule: 進行中 when any of — a live dispatch run in scope; a session task `in_progress`; the session's turn is active (the attention/session state shows activity after the last Stop/idle — derive the exact signal from the W1de writer, quote file:line; if no signal distinguishes "turn active" from "turn ended", report it and use: task in_progress OR live run). 待命 only after Stop/idle with no live run and no task in progress. Fix in `mods/live/model.ts` with RED-first tests.
2. **完成待驗收 requires no live run** (capture `df-running-3`: tasks all completed + one live dispatch → band 進行中, which is right). Precedence stays 要你決定 > 疑似卡住 > 完成待驗收 > 進行中 > 待命, but 完成待驗收's condition is "(campaign frozen done == total OR every session task completed) AND no live run in scope". Confirm the mod does exactly this (test it); update `gate/check.js` to the same rule.
3. **Dialogs cover the band** (captures `df-perm`, `df-ask`): when a permission or AskUserQuestion dialog is open, the band row is hidden but the mod's top-right panel shows the verdict. `gate/capture.sh` records both the band row and the panel line(s) (find the panel's on-screen marker in `DRIVING.md`); `gate/check.js` uses the band when present, else the panel, and prints which surface it judged (`surface: band|panel`).
