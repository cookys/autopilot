- **第 1 段（replay，≤10 段事件、≤5M）**：只在 PM 看過第 0 段數字、認為有疑問的開關才跑。下文 §3 隔離、§6 的 80M 總額與白名單池只適用第 1 段；第 0 段不用模型、不佔池。

## 1. 問題

S1 每日數字前後比，會被當天工作量和種類干擾。反例：S2 上線當天剛好有 3 個 patrol 風暴，成本上升，有效開關被誤判無效；反過來某天很安靜，無效開關被誤判有效。replay 固定輸入、一次只改一個開關。

## 2. 語料與資料界線

- **事件**＝一則進來的訊息（操作員、lane 結果、patrol、inbox 批次、stop-hook 回饋、task 通知）加上它引發的所有回合，到下一則進來的訊息為止。
- **切片器** `scripts/pm-replay-slice.js` 由 PM 帳號執行；本席不讀 PM 原始 transcript，只收 PM 交出的產物。判不出類型的歸 `other` 並計數。
- **PM 交出的全部產物**一律走同一關：fixture、各 L 的預填前綴、CLAUDE.md 與 memory 快照。掃描分兩級，在 PM 帳號的切片器內、抽樣之前執行（抽樣只從通過的件取，配額不足即中止）：(1) 真金鑰、token、憑證、高熵祕密命中，整件丟棄並記數；(2) 非祕密識別字（家目錄路徑、私有主機名、email）替換成固定占位符並記次數，不整件丟。規則檔進 manifest 並記 sha；manifest 記每件 sha256 與整批 sha256，PM 只執行本席審核並釘死 commit 與 sha256 的切片器，執行時斷網、對原始 transcript 唯讀、只寫指定輸出目錄；「簽署」＝PM 在 fleet 單上以其被證實的 from 回報 manifest sha256 與掃描報告 sha256（不另做密碼學簽章）。掃描未通過的件不得使用，本席不得回讀原始 transcript 補件。
- **預填前綴**：每個 L（100k、150k、250k、300k、350k、450k，含基準臂 300k 與 S6 PM-chat 100k）一份，取自 fixture 之前的真實回合，截取規則（起點、截斷點、不切到 tool 配對中間）寫進 manifest。
- **抽樣**：依類型分層 30 段（operator 8、lane 結果 7、patrol 5、inbox 批次 5、stop-hook 回饋 3、task 通知 2），固定種子；凍結後不改，換批就換新 manifest 編號。
- **fixture 內容**：事件輸入、錄到的每次工具呼叫（名稱、正規化參數、原始結果）、錄到的決策標籤（見 §4）。

## 3. 重放與隔離

- 在 sandbox HOME 內用 Claude Agent SDK 跑一席 PM：同模型、同一份凍結的 CLAUDE.md 與 memory 快照、各臂釘各自的 plugin commit。
- **強制隔離（凍結前即規格，不留給實作裁量）**：作業系統層用 bwrap（獨立 mount、網路 namespace）：不掛真 HOME、真 repo、真設定目錄與本機 fleet／bus 的 socket，plugin 以不含 .git 的唯讀副本掛入，網路只通模型 API 端點；其內再做：空白暫存 cwd；環境變數白名單，清掉 fleet、git、SSH、token、`CLAUDE_CONFIG_DIR` 指向真目錄的值；停用 SDK 全部內建檔案、Bash、網路工具，只開自訂 stub 工具；MCP 設定為空且 strict；plugin 與 hook 只載入臂指定的、在同一 sandbox 內執行；
- **stub**：查表鍵＝（工具名、正規化參數 hash）；同鍵重複呼叫依錄製順序消耗，順序對不上的標「分歧」。命中回錄到的原始結果；未命中回 `{"stub":"no_recording"}` 並標「分歧」。預期會改變工具參數的開關（如 S2）另設正規化規則與預期行為 stub，與意外未命中分開計數。
- **負控制（harness 通過條件）**：合成事件分別嘗試真 fleet 發送、真 repo 寫入、讀真設定目錄、直接網路出口、hook 子行程旁路；每項必須被拒，以本地哨兵與拒絕紀錄驗收，不用真 fleet 做測試。任一項未攔住，harness 不通過。

## 4. 比較方法

- **配對**：正式成本差只在 ON、OFF 兩臂都有效（非分歧）的同一批事件上算；另報完整樣本成本、各臂分歧率、分歧類型與原因。開關造成的系統性分歧（某類事件只在一臂分歧）視為「不可判定」，不能靠刪事件取得上線資格；修補 stub 後以同一版 fixture 重跑受影響的配對臂。分歧超過 30% 的臂無效。
- **treatment manifest**：每個比較凍結唯一允許的差異（plugin commit 或旋鈕）。每個事件都從不可變的預填前綴獨立重置，事件間不累積 context；快取條件固定同一 TTL 等級，每臂每事件驗收 cache_read 命中，不符的事件標分歧；臂的執行次序交錯（ABBA），基準臂僅在版本、context、快取條件都相符時共用，否則重測。每臂量測前先做一次獨立暖快取呼叫（不計成本與分歧），ABBA 區塊時間低於快取 TTL，接近 TTL 時兩臂對稱重暖；每事件前除重置 context 外也重置 sandbox 檔案狀態。基準臂 L 固定 300k，與 S6 的比較法見下表。
- **指標**：加權成本（read 0.1、cache write 5m 1.25／1h 2.0、input 1、output 5）、回合數、機械呼叫數、決策一致率。
- **決策標籤**：事件中所有有副作用動作的正規化意圖集合（動作類別＋目標，如 dispatch 對象席位、accept 的任務 id、關鍵參數），允許一組有效答案。評分：單事件二元，動作類別、目標、關鍵參數正規化後集合完全相等才算一致；無副作用呼叫的事件（如操作員問答）以「集合為空且回覆類別相同」計，不給空集合免費過關；有效答案集合在重放前產出並凍結進 manifest。一致率分母＝完整凍結樣本 N，分歧一律計不一致，另列配對子集的一致率；兩者都不得低於基準臂 5 個百分點才能放行，基準臂分歧率超過 30% 則基準無效、重做 stub。若把分歧全部排除後結論會翻轉，判「不可判定」，不得上線。低於基準臂 5 個百分點的開關不得上線；篩選輪 12 段時一段占 8.3 個百分點，故篩選輪只能「淘汰」開關，不能「放行」開關，放行須完整輪。

## 5. autocompact 的模擬

臂先預填到 L（暖快取，預填成本另記不入量測），再在同一 L 下重放同一批事件，得到成本對 L 的曲線；再補入每次壓縮的摘要呼叫成本、壓縮後快取重建成本，並以 PM 席實測壓縮間隔估整日平均 L。摘要失真對決策一致率的影響另跑一組：壓縮後的 context 重放，比一致率。全部報為模擬。

## 6. 成本與池

- 估算（試跑 dry run 3M、篩選輪 15M、完整輪約 52M 含預填暖身與 autocompact 一致率臂、修補重跑預備金 10M，合計 80M，約 PM 4 天基準 317M 的 25%）：一事件約 1.5 回合、加權約 170k；30 事件一臂約 5M。完整輪：基準加 S2、S5b、S6 共 4 臂（S4、S5a 無 LLM 臂）約 20M，加 autocompact 4 個 L 約 20M，含預填暖身與快取重寫約 +30%，合計約 52M，約 PM 4 天基準（317M）的 16%。
- 篩選輪 12 事件、只跑基準與有疑問的臂，約 15M。完整輪整個計畫最多 1 次。
- **總額上限**：試跑、篩選輪、完整輪、修補重跑共用一個總額 80M，寫進 manifest，各階段上限之和不得超過它；累計器計入所有實際發出的模型呼叫（預填、暖快取、失敗、重試、dry run、重跑）；每次呼叫前預留該事件最大可支出量；SDK 層設每事件 maxTurns 與每臂硬上限；累計超過預估 150% 即停、整輪作廢，不得另開一輪重置額度。
- **池**：fail-closed 白名單：manifest 寫入至少一個可跑 PM 同模型、與 PM 主備援額度完全隔離的非 PM 池 id（凍結前由 PM 指認）；harness 啟動前必須取得非空池 id 且在白名單內，否則拒絕。同模型跑不起來時，小一級模型只做 dry run（驗 stub 與一致率計算）。
