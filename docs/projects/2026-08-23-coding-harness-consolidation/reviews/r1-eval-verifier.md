# R1 — Evaluator / Verifier attack review

> Independent pass. This review focuses only on whether the proposed decision can be falsified locally without vendor quota.

## Findings

### 🔴 Critical — No exact deterministic test suite is specified

W1–W3 are scenarios, not tests. There are no fixture names, injected failure points, expected call counts, or exact exit/result assertions.

**Smallest fix:** the plan must require one credential-free conformance suite with four fixtures.

## Required fixtures

### F1 — projection parity and planted drift

Purpose: distinguish generated package copies from manual forks.

Steps:

1. Run the existing Codex and OpenCode `--check` generators.
2. Ask the inventory command to classify every projected path.
3. Copy a generated file into a temp fixture and alter one authoritative field.
4. Re-run the checker against the temp projection.

Oracle:

- clean tree: pass;
- planted mutation: fail with the exact source/destination pair;
- generated bytes are reported separately from manual edit owners.

### F2 — implement committed, review not started, then resume

Purpose: prove W2 without a daemon.

Setup:

- temporary Git repository;
- fake implementation dispatcher that creates exactly one commit and increments a durable call counter;
- fake review dispatcher with a valid deterministic verdict;
- injected termination after implementation receipt/commit but before review invocation.

Resume oracle:

```text
implementation call count = 1
review call count = 1 after resume
base SHA unchanged
candidate HEAD is descendant of base
no duplicate commit
next phase = review/verify, not implementation
```

### F3 — invalid reviewer output is fail-closed across surfaces

Purpose: prove canonical semantics are not changed by packaging.

Setup: fake reviewer returns malformed or empty capture.

Oracle for root and Codex-packaged CLI:

```text
same semantic status = blocked/no_verdict
same authoritative phase
non-success exit according to the public CLI contract
zero merge calls
zero closeout success claims
```

### F4 — Pi directive capability without a live model

Purpose: prove W3 at the worker boundary without turning every host into a duplex client.

Setup: fake Pi RPC child emits the expected typed event sequence and records `steer`/`abort` input.

Oracle:

```text
steer receipt is correlated to the active run
abort is idempotent
post-abort terminal event is observed
unsupported runners are reported as non-duplex rather than emulated
```

A separate opt-in live smoke may reuse the existing capability receipt and Pi RPC path, but it is not part of the normal gate.

## Decision thresholds

- If F1–F4 pass and `manual_duplicate_paths` is empty or bounded to genuine host adapters, select Option 0 and stop.
- If a manually maintained duplicate implements canonical semantics already available in root core, move only that logic to root and select Option A.
- A service/runtime spike remains barred unless F2 demonstrates that resumed CLI cannot safely reconcile at two distinct real effect boundaries.
- Pi/DSH primary-runtime comparison remains barred unless a required fixture cannot be satisfied by Option 0/A and the missing capability is named.

## Loop discipline

- R1 may find architectural/test gaps and must prescribe the smallest fix plus its oracle.
- One consolidation repair is allowed.
- R2 may only verify closure of R1 findings and detect regressions introduced by that repair. It may not open unrelated improvements.
- R2 failure ends the plan at `BLOCKED/BOARD`, not another review generation.
