# Agent-driven gate run (owner 2026-10-05: "這些你無法處理嗎?" → depth-0 drives the real-machine gate itself)

The gate's substance is real `claude` processes with the live plugin (main checkout 2160351c via the dev symlink), real hooks, real stores, band text re-derived from same-moment files by `check.js`. An agent driving real interactive Claude Code sessions in tmux on this host meets it. The owner keeps: eyeballing a few captures for readability over ssh, and the release/push approval.

## Driver rules (every gate hand)
- **Private tmux server**: `tmux -L gate …` only. Never touch the owner's default tmux server. The owner can watch read-only with `tmux -L gate attach -r -t <session>`.
- **Clean environment for the server** (a nested `claude` refuses or misbehaves under a parent session's env): start it with `env -i HOME="$HOME" PATH="$PATH" TERM=xterm-256color LANG=C.UTF-8 USER="$USER" SHELL=/bin/bash XDG_RUNTIME_DIR=/run/user/1000 tmux -L gate new-session -d -s <name> -x 200 -y 50 -c ~/projects/gate-sandbox`. Do NOT pass `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `AUTOPILOT_SESSION_ID`, `AUTOPILOT_LIVE_DIR`, `CLAUDE_CONFIG_DIR` (never set it: the real `~/.claude` must be used as is).
- **Launch**: in the pane, `CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude --model sonnet --permission-mode acceptEdits` (Bash still prompts — needed for the permission cell). The first launch in `gate-sandbox` may show the trust-folder dialog (default "No, exit"): send Down, then Enter, to trust.
- **Targets**: always `-t <name>:` (trailing colon). A bare `-t c` prefix-matched the other session `df` in the pilot and typed into it; never rely on a default target in a helper. Set `GATE_TMUX_SOCKET=gate` for `capture.sh`.
- **Typing**: `tmux -L gate send-keys -t <t> -l '<text>'` then a SEPARATE `tmux -L gate send-keys -t <t> Enter` (paste-burst). The driven Bash refuses a bare foreground `sleep N`: when a command must wait, give it as a `for` loop (approve once). Give every dispatch command with the ABSOLUTE script path (else the driven session runs `find /`), and `--model gpt-6-astra` for codex (`dispatch-hetero.sh` refuses a non-agy runner without `--model`, and codex runs with `--ignore-user-config`, so the `~/.codex/config.toml` default never applies; `--model gpt-5.5-codex` is a 400 on this account). Wait for the turn to finish by polling `capture-pane -p` (no spinner / prompt visible) in a foreground loop with a hard cap; never park.
- **Session id**: diff `ls ~/.autopilot/session-mode/` before and after launch; pass the new id explicitly as the 3rd argument to `capture.sh`.
- **Isolation is INVERTED here**: no live-dir/marker-dir overrides — the real stores are the point. Record every session id, marker file and scope key the run created (`gate/runs/<mode>/created.txt`) so depth-0 can clean up later. Never touch the autopilot repo itself from a driven session; only `~/projects/gate-sandbox` (reset it between modes: `git -C ~/projects/gate-sandbox fetch -q origin && git -C ~/projects/gate-sandbox reset -q --hard origin/develop && git -C ~/projects/gate-sandbox clean -fdq`).
- **Cells**: per `RUNBOOK.md` §1 (six cells: 要你決定 permission and question, 疑似卡住 (STOP a silent hand by pid, see RUNBOOK), 完成待驗收, 進行中, 待命; a dialog hides the band, `check.js` then judges the panel and prints `surface: panel`) + the mode's extra cells (§2, §2b). For each: trigger → wait ≥ 20 s (疑似卡住: ≥ 200 s) → `GATE_TMUX_SOCKET=gate bash $G/capture.sh <mode>-<cell> <window>: <sid>` (captures land in `gate/runs/<mode>-<cell>/<UTC timestamp>/`) → `node $G/check.js <dir>`. FAIL captures are never re-run in place; a retry gets a new cell name with a reason.
- **Blocked cells**: when the rail/sandbox refuses (roster, endpoint, intake config), record `BLOCKED: <exact error>` with the capture; spend at most ~10 minutes on sandbox config; never fake a cell; move on.
- **End of mode**: exit the driven `claude` (`/exit`), kill the tmux session, append rows to `gate/runs/RESULTS.md` (mode, cell, PASS/FAIL/來源未接/BLOCKED, capture dir, note), and report spend if visible.
- **Budget**: stop and report if the mode exceeds 45 minutes wall or the sonnet quota errors (do not switch the driven model).
- **Approve loop: approve only what you expect (a blanket Enter is forbidden).** A permission dialog is approved only after matching its text against the ONE command you expect (`capture-pane -p` shows `Bash command` / the command line inside the box): approve (Enter, or `1`) only when the command line contains the expected command string; any other dialog is left open and recorded (deny with Escape if it must go). Never loop `send-keys Enter` blindly: in the /l4 gate a stray Enter accepted a ghost prompt suggestion and pushed the sandbox origin. Shape: `for i in $(seq 1 N); do P=$(tmux -L gate capture-pane -p -t <t>:); if grep -qF -- '<expected command text>' <<<"$P" && grep -q 'Do you want to proceed' <<<"$P"; then tmux -L gate send-keys -t <t>: Enter; break; fi; if grep -q 'Do you want to proceed' <<<"$P"; then echo "UNEXPECTED dialog" >&2; break; fi; sleep 2; done`. A dialog raised by a SUBAGENT ("from the general-purpose agent") is full-width and hides the band and the panel: `check.js` then prints `surface: dialog` and judges 要你決定 from `attention.json` alone.
