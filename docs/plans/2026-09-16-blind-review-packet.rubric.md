R1: `src/runners/review-packet.js` exports `buildReviewPacket`, `packetPathDenied`, `normalizeDenyList` and `DEFAULT_PACKET_DENY_LIST` (exactly the eight patterns of plan §1.1); the packet holds `tree/` (git archive of the candidate via `--output`, denied paths pruned, symlinks kept as symlinks), `diff.patch` (input diff split into Buffer sections aligned to `git diff --name-status -z` records, denied old-or-new-path sections dropped, kept sections byte-for-byte), `spec.md` (byte-for-byte, zero bytes when absent) and `MANIFEST.json` with full OIDs, normalized `deny_list`, sorted `entries[{path,type,sha256,bytes}]` and `packet_hash = sha256(JSON.stringify({schema_version, base_sha, candidate_sha, deny_list, entries}))`; no timestamp, absolute path, hostname or PID appears in the manifest.
R2: Packet canary — a fixture candidate whose commit message, an untracked worktree file, eight deny-listed tracked carriers (`.autopilot/`, `.qc/`, `docs/plans/evidence/`, `*.review.md`, `*disposition*.json`, `*.receipt.json`, nested and root `*.raw.log`) and a file renamed out of a denied directory each carry a unique token yields zero grep hits over the built packet, while the allowed product, binary and CRLF files are present in `tree/` with the candidate's bytes and their diff sections are byte-equal to the input's; a content line starting with `diff --git` does not start a section (RED at base: module absent).
R3: Packet hazards — a safe relative symlink survives as a symlink; an escaping symlink and a symlink to a denied path are pruned and listed in `denied_paths`; a gitlink fails the build closed with `unsupported submodule: <path>` and writes nothing under `outDir`; a >1 MiB archive builds; an absent `specFile` yields a zero-byte `spec.md` listed with `bytes: 0`.
R4: Packet identity — two builds of the same inputs give the same `packet_hash`; one changed spec byte gives a different one; a reordered/duplicated deny-list gives the same one; manifest entries equal the sorted `lstat` walk (manifest excluded) with every sha256 and `type` re-verified; `base_sha`/`candidate_sha` are full OIDs; the test re-computes `packet_hash` from the pinned preimage; with `denyList: []` and no hazards `diff.patch` is byte-identical (`cmp`) to the input; the `packetPathDenied` / `normalizeDenyList` tables in plan §2 hold.
R5: `dispatchReview` with `blindDiscovery: true` and `options.packet = { repo, baseSha, candidateSha }` launches the script with `--diff-file` ending `/packet/diff.patch`, `--spec-file` ending `/packet/spec.md` only when a `--spec-file` arg was given (a zero-byte `packet/spec.md` otherwise, no arg added), env `AUTOPILOT_REVIEW_PACKET_DIR` (that dir), `AUTOPILOT_REVIEW_PACKET_HASH` (64-hex) and `AUTOPILOT_BLIND_DISCOVERY=1`; `dispatchReviewJson` returns `packet.packet_hash` equal to the env value (RED at base).
R6: Fail-closed and branch parity — a packet build failure (nonexistent candidate) returns `error` set, `status: null`, `packet: null`, and the script is never invoked (RED at base); the child-error, parse-error and missing-script branches of `dispatchReviewJson` all carry `packet: null`.
