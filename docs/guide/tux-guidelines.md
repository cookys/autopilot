## 1. 四層資訊架構（L0–L3）與版面規則

核心鐵律：**單一事實只出現於唯一位置（One Fact in One Place）**，將 `FACT_OWNER`（`mods/live/ui.ts:385-400`）由跨分頁延伸至同畫面跨層，嚴格分離「狀態摘要、清單導覽、單卡內文、底部控制」。

### 熱區（Hot zone）原則

依 PM 裁示 `01M773F3`（2026-11-12），版面配置以**熱區（Hot zone）**為最高指導原則：
- **規則定義**：
  1. **操作本體貼底（Act-on at bottom）**：操作者當下必須動手的項目——正在決定的卡片本體、其選項按鈕、以及送出／撤回控制列——一律置於窗格最底部，緊鄰宿主輸入框（input box）。
  2. **決策依據同行並排（Deciding context beside, in the same rows）**：做出該決定所需的資訊——背景（`background`）、建議與推薦理由（`recommendation`／`why`）、以及相關的最近提問與回覆（「我問的問題」）——必須置於當前卡片**旁邊（同一批水平列內左右並排）**，嚴禁拆到上方獨立區塊迫使視線上下跳躍。
  3. **其餘資訊置頂且可收合（Cold zone above & collapsible）**：所有非當下動手的總覽資訊——全局摘要列（summary lines）、待決佇列總覽（queue overview）、資料年齡（data-age）與異常清單——一律置於熱區上方，且支援收合（collapse）。
- **設計理由（Why）**：操作者以底部的宿主輸入框為作業原點（打字向 PM 提問、按 `f` 填入 `[待決回覆]` 模板、切換焦點選答皆從輸入框出發）。若將待決卡推離底部，或把背景、建議與最近問答放在上方獨立區塊，眼球就必須在底部輸入框與中上段視窗間反覆大幅垂直往返（vertical eye travel）；把操作本體貼底、決策依據同行並排，視線只需在底部幾列內水平掃視即可完成判斷與送出。
- **對 L0–L3 的由上而下排序約束（v1 → v1.3 修正）**：
  - **上方冷區（Cold Zone，可收合）**：**L0**（頂部單行狀態帶，為待決總數 `(N)` 之唯一呈現處；指揮台之 `summaryRow`、`ageRow` 資料年齡與可收合 `exceptions` 皆置於此，修正 `band.tsx:265` 選單夾底與 `commandtab.ts:139` `ageRow` 壓底）→ **L1**（全寬單行待決佇列總覽，展開與收合皆不重複總數 `(N)`，收合為 1 列 `▸ 待決佇列`；修正 v1 將「我問的問題」混入 L1 上方區塊之設計）。
  - **底部熱區（Hot Zone，緊貼輸入框）**：**L2**（直接位於 L3 正上方；`>= 100` 欄採左右雙欄並排——含 `>= 120` 欄與 `100–119` 欄——且雙欄皆**貼底對齊 `justifyContent="flex-end"`**：**L2 左欄**放當前選中卡題目、選項與不授權，**L2 右欄**於同一批列貼底放「我問的問題」（`>= 120` 欄）、背景與最底列的建議理由；`Pane`／PM 指揮台於高視窗中以冷熱區間的彈性墊高或底部錨定讓 **L2+L3 共同貼底**，中間絕不留空列）→ **L3**（最後可見操作列，緊貼輸入框，集中放置選項／背景／補充／佇列收合 `q`／翻頁／送出／撤回等全部有效按鍵提示）。

### 展開高度、色彩語意與窄寬度（80–119 欄）熱區退讓順序

- **內容驅動高度（上限 `Math.min(maxRows, Math.floor(rows * 0.6))`、禁全列空白填充）**：展開區總高度 = `冷區列數 + 熱區 max(L2 左欄, L2 右欄) + L3 列數 + 外框`（`Pane`／指揮台另含 `scrollFrame` 底部的 1 列 `spare` 列於高度預算內），隨內容伸縮，上限嚴格為 **`Math.min(maxRows, Math.floor(rows * 0.6))`**（同時受終端機總列數 `rows` 的 60% 與宿主傳入之 `e.props.maxRows` 夾制，避免 `maxRows < Math.floor(rows * 0.6)` 時宿主以 `"n more"` 遮蔽 L3）。超出上限時於 L2 右欄依據或超長卡啟用捲動視窗與 1-cell 捲軸（`cardSplit`、`fixedWindow`/`thumbOf`，`mods/live/band.tsx:365-383`、`mods/live/scrollmath.ts`），左欄選項與 L3 釘死底部不捲動。廢除 `BODY_ROWS = 8` 保底（`shell.ts:20`、`register.ts:1370`）與跨全欄純空白填充列（`band.tsx:378`、`shell.ts:270`；雙欄 `justifyContent="flex-end"` 較短一欄上方的單側補空不在此限）。
- **色彩與強調（遵循 `mods/CLAUDE.md:7`、`mods/live/design.md`、`mods/live/ui.ts:79-99`）**：僅透過 `PALETTE`（`ui.ts:87`）使用 8 個語意文字色（`attention`/`here`/`broken`/`done`/`running`/`idle`/`structure`/`action`），嚴禁 `backgroundColor` 與 `inverse`（`ui-lint.test.js:133, 241`）；粗體僅限 `BOLD_USES` 7 處（`ui.ts:89-99`）；符號取自 `GLYPHS`（`ui.ts:65-75`）並經 `mods/live/glyph-check.js:7-15` 單格驗證。

設計與實作須在 Claude Code 終端機宿主（Host TUI）對 `AbovePrompt` 與 `Pane` 之硬性邊界內運作：

1. **狀態帶（Band）無備用列，側欄／指揮台（Pane／PM Console）保留 1 列自繪 `spare` 列**：

   - **側欄 `Pane` 待決分頁與 PM 指揮台（必留 1 列 mod 自繪 `spare` 列）**：兩者將 L3 置於 `scrollFrame`（`mods/live/pane.tsx:48-50, 190-194`），而 `mods/live/scroll.tsx:87, 123` 於固定高度外框下方刻意繪出 1 列 `<Text key="spare"> </Text>`；`mods/live/live.test.ts:6142` 與 `mods/live/scroll.tsx:5-6` 證實渲染樹必須比視窗高出這 1 列，引擎才會觸發 `ui.scroll` 事件（若移除將導致長卡無法捲動）。因此 `Pane`／指揮台必須在固定 `bar` 下方保留這唯一 1 列由 mod 自繪之 `spare` 列，並將其計入高度預算內。

`△`、`▴`、`▽`、`◇` 不著 theme key，避免跟「要你動手」的 `warning` 撞成一色兩義；這四個狀態靠符號區分。百分比本身不著狀態色。`正常` 用 `done`，與既有「不必再動」同一語意。不用 `●`。

codeforge 的 `warn` 與上表可能不同。兩者都要時必須標來源，禁止合成一個狀態。`pool-a-team`：上表狀態是落後（`▽`，提議差距 −28），列尾 `cf:浪費` 是現有 `weekly.warn=waste`。`pool-b-main` 與 `pool-b-spare` 達 L3（`projected` 1.04 與 1.01，耗盡早於重置 37h 與 31h，皆超過 6h），狀態符是 `✗`。差距欄的 `▴21`、`▴18` 只表示超前線性，不著 `warning`，也不取代 `✗`。純超前（沒有更高狀態）時，狀態符才是 `▴`，差距欄改寫數字、不再畫第二個 `▴`。本 fixture 沒有那種池，L30 用合成列測它。也沒有非 Claude 的浪費池，`◇` 只在規則裡，不在圖裡。

同一批 key 的其他元素（不新增語意）：

| 元素 | role | 與上表的關係 |
| :--- | :--- | :--- |
| 標題 `⋯` 與 `快取` | idle，且 `dim` | 與不新鮮同一個「沒有新鮮訊號」 |
| 標題 `剛更新` | structure | 標籤，不是狀態 |
| 熱區告警句的 `✗` | broken | 與該池的 L3 是同一個符號。狀態 3 把 `pool-b-main` 的 `✗` 從數字列移到告警句，不畫兩次 |
| 可按的 kind `a`、`c` | action | 按得動。整列這個色，不加 `▲` |
| kind `a*`、`b` | attention | 要操作員動手，與 L2、急迫徽章同一語意 |
| 單次高亮的 `✦` | here | 這一幀的焦點。下一幀拿掉 |
| 到點列的「到期」 | running | 此刻正在生效，沿用「正在進行」 |
| 徽章「久」 | idle | 與不新鮮同一個「沒有新鮮訊號」 |
| 徽章「▲急」 | attention | 要你動手 |

kind 的優先序是 `a`、`c`、`a*`、`b`。`a`：token 已在那台主機，lane 直接換池，不需操作員。`c`：改派非 Claude 引擎；資格由 autopilot 定，capacity 只給剩餘。`a*`：要複製 token 或重新登入，需操作員同意，帶 `card`。`b`：操作員親自 `/login`。熱區只把第一則畫成全文，欄位是 `lane`、`from`、`to`、`kind`、`reason`，不寫百分比。其餘則數若大於 0，收成 `▸ 另 N`，不展開第二則。mockup 只有一則，不畫 `▸ 另 0`。那一則是提議樣本：kind `a`、lane `recovery`（fixture 的 `top_lines`）、from `pool-b-main`、to `pool-a-new`、主機 `fx-host-d`（fixture 的 `hosts`）、沒有 `card`。建議列畫成 `[a]`、lane、接著 `from>to`（`pool-b-main>pool-a-new`）、再寫 reason。來源池在 120、160、200 都不省略。

熱區告警句只提升最嚴重的一池。本 fixture 是 `pool-b-main`（耗盡 14h，早於 spare 的 20h）。沒有告警句的狀態（1 與 2）把 `耗14h` 寫在 main 的數字列；狀態 3 改寫在左欄 `剩14h`，數字列不再寫。spare 沒有自己的告警句，所以 `耗20h` 一直在它的數字列。`└ recovery 佔52%` 是 pool-b（main 與 spare）的 `share`，全表只此一次；它貼在 spare 下面，是為了讓 main 那一列跟告警對齊，不表示這 52% 只屬於 spare。

### 6.5 同一熱區的三條卡片規則

1. **新卡或更新的卡**：一次短動畫，或一次高亮，然後停住。禁止連續閃爍，禁止 `blink`，禁止用計時器反覆開關高亮。mockup 畫的是高亮那一幀：`✦`（`GLYPHS.structure.fresh`）著 `PALETTE.here`。下一幀拿掉 `✦`，標題留著，顏色回到預設。本 fixture 最新的卡是 `card:d-fe000003`（`since_ms` 距 `generated_at_ms` 6 分），列上用它的 `title`。
2. **待決徽章**：三個互斥的桶，三個色。一張卡只進一桶，優先序是急迫、到點、逾 4 時。急迫是卡片物件上的提議欄 `cards[].urgent` 為 `true`，不是每個 `need_you`（fixture 四張卡都是 `need_you`，若用那個當急迫，另外兩色永遠是 0）。到點是卡片物件上的提議欄 `cards[].due_text` 的時刻已到。逾 4 時是 `generated_at_ms − since_ms > 4h`，且沒有前兩項。不進桶的張數仍只在 L0 的 `(N)`。mockup 的 `▲急1` 是 `d-fe000003`（示意標成急迫），`期1` 是下一條的到點卡，`久1` 是 fixture `card:d-fe000002`（`facts.age_h = 18`，未標急迫、無 `due_text`）。三個 id 只在本段點名，徽章上只留計數。
3. **到點提醒**：`cards[].due_text` 的時刻一到，卡自己出現在熱區，不必打開佇列。未到不畫。mockup 的「明天到公司後」是操作者給的例句，fixture 沒有這欄。列上寫 `到期` 與那句話，不寫 `期1`。

這三條在九張 mockup 都在。有建議時，告警與建議佔最底兩列，三條卡片往上讓一列，仍在熱區，不回到冷區。
