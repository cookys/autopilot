# Frozen rubric — Operator Asks List

- R1: [identity] Does the plan define a reliable grouping identity and lifecycle for repeated questions, including unbound questions and preventing unrelated questions from merging?
- R2: [reply] Does the plan specify how queued input and tool-only turns map replies to the correct ask, with reachable hook events and meaningful negative controls?
- R3: [disposition] Does the plan specify safe, implementable progress and close triggers, including how evidence identifies the correct ask and avoids false closure?
- R4: [data contract] Are the fields, status transitions, timestamps and existing askpm data compatibility specified sufficiently for the proposed view to be implemented?
- R5: [integration] Are the codeforge and fleet boundaries, ownership, dependencies and verification of the proposed shared interface concrete and consistent with repository evidence?
- R6: [execution] Do the task breakdown, dependencies and acceptance tests cover every proposed behavior, including repeat-answer injection and negative cases?
- R7: [measurement] Are the baseline, target, measurement method and rollout criteria sufficiently defined to assess the stated outcome after one week?
- R8: [operational risks] Does the plan bound transcript scanning and address concurrency, persistence and privacy risks of recording and resurfacing replies?
