# Rubric — depth-0 decides the per-turn gate (BL-0055 follow-on), frozen for plan review

- R1: [fact-fidelity] Every claim about the existing per-turn-gate hook (knobs, fail-open, max_blocks, log contract, how it reads config), about the evaluated verdict (mode, task, model, numbers) and about harness capabilities (SubagentStop fields and block semantics, which harnesses run autopilot Stop hooks) matches the cited source or official document, and anything not verified is labelled unverified rather than asserted.
- R2: [owner-intent] The plan delivers what the owner asked: the decision to arm the gate belongs to depth-0 per task, not to a user-edited global setting, and the global default stays off; any place where a user or global setting can still override depth-0 is stated and justified.
- R3: [mechanism-safety] The session or lane switch cannot arm the gate for sessions it was not meant for, cannot outlive its task, fails open on any error, and keeps the existing hook behaviour unchanged when nothing new is configured; each new check ships with a negative control shown red before green.
- R4: [verifier-soundness] The generic verifier and its rule-list schema let depth-0 describe constraints as data rather than write code; the exit-code contract matches the existing verifier interface; a malformed list, an unsafe command or a path outside the repo cannot block work or run arbitrary code; and the plan states how a wrongly filled list is detected or bounded.
- R5: [target-correctness] The gate checks the worker that does the work (dispatched hand or subagent), not depth-0's own session, for every dispatch path the plan claims to cover, and paths that cannot be covered are excluded explicitly.
- R6: [mechanism-guidance-split] Mechanism changes and the guidance that tells depth-0 when to arm the gate are in separate phases and commits; the guidance phase is gated on an ON/OFF evaluation whose arms, markers, negative and positive traces, decision rules, cost estimate and cap are specified well enough to preregister.
- R7: [plan-hygiene] Phases have executable done-conditions and a coherent order; owner decisions and paid steps are listed with costs; ADR-0001 and the version hold are respected; the document is self-consistent and stays under 30 KB.
