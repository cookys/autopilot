# replay 真 runner 的憑證做法：沙箱外代打 API 與憑證帶進沙箱的比較

Status: 供 PM 裁定（PM 11-25 要求 11-29 前交一頁）；fleet 單 01M838P3WFXNM885HK3S6ZGSXP；上位計畫 `2026-11-23-pm-replay-measure.md` §3、§6。
本頁只比較做法，不含任何憑證內容，也沒有讀任何憑證檔。

## 要解的問題

replay 的模型呼叫要從 bwrap 沙箱（預設無網路）裡發出。計畫 §3 規定沙箱只有模型 API 這一個出口，且真 HOME、真設定目錄不得進沙箱。真呼叫需要認證，認證從哪裡來，就是這兩種做法的差別。

## 做法 (a)：沙箱外代打

- 沙箱外跑一個很小的代理（本機 Unix socket），沙箱內只掛這一個 socket；網路 namespace 維持不共用。代理只轉發模型 API 一條路徑，認證由代理在沙箱外附上，沙箱內的程序看不到也拿不到。
- 沙箱內的 CLI 或 SDK 把 base URL 指向代理（沙箱內需一個把 socket 接成本機埠的轉接，這一步能不能用現有 CLI 設定達成**待驗**）。
- **要複製 token 嗎**：不要。代理沿用發起席位本來就在用的認證，不產生副本。
- **碰到哪些憑證**：只有代理程序在沙箱外讀取發起席位已有的那一份；沙箱內零憑證。
- **隔離會破嗎**：不破。五項負控制照舊；多一個「沙箱內除代理 socket 外無其他出口」的探針，和一個「代理拒絕非模型 API 路徑」的探針。
- **額外好處**：代理是 API 邊界，天然是預算累計器的唯一計量點（§6 要求累計所有實際發出的呼叫，含失敗與重試），也能硬性擋超額。
- **風險**：代理本身是新程式，需審查與測試；若 CLI 不支援自訂 base URL 走本機埠，要改用 SDK 直接呼叫（此時模型迴圈在沙箱外，沙箱只負責 hook 與 plugin 的執行）。

## 做法 (b)：憑證帶進沙箱

- 把一份憑證檔放進沙箱內的暫存設定目錄，沙箱開放通往模型 API 的網路出口。
- **要複製 token 嗎**：要。這是複製憑證，依全域規則屬操作員卡（不是 PM 或本席能決定）。且既有經驗是複製出去的 OAuth 副本約 3 小時失效，長輪要反覆重新複製，每次都是一次憑證動作。
- **碰到哪些憑證**：發起席位的憑證檔本體，進到一個會跑「被測 plugin 與 hook」的環境。
- **隔離會破嗎**：會變弱。沙箱內有真憑證，又要放開網路出口，被測的 hook 或 plugin 若有缺陷，可能讀走憑證或對任意位址送出；「網路只通模型 API」要靠 egress 白名單再補，而 bwrap 本身不做域名過濾，需要另一層代理，等於還是要做 (a) 的代理。
- **風險**：憑證外洩面、過期重複複製、白名單另需代理。

## 建議

做 (a)。它不複製憑證、不需要操作員卡、隔離不退讓，還把預算計量收斂到單一點；(b) 最後也得靠代理才能守住出口，沒有省工。

## 做法 (a) 的前置與日期

1. 驗證 CLI／SDK 能否把 base URL 指向沙箱內轉接的本機埠（零 token，用本地假 API 測）：11-28 前。
2. 代理與兩個新探針由便宜席實作、本席審：11-29 前提出，不需憑證即可用假 API 驗證全部負控制。
3. 真呼叫只在完整輪 11-29T20Z 之後、PM 指認池之後才發生；到那時用哪個池與哪份認證仍由 PM 裁定，並以代理沿用既有席位認證、不複製為前提。若 PM 判定仍需操作員卡，在那之前代理與探針先以假 API 完成。

## 不做

不讀憑證檔、不複製憑證、不開放沙箱一般網路。
