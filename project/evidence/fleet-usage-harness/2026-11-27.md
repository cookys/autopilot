# 四個 harness 是否讀到 fleet watch／upload／fetch（2026-11-27，單 01M81M4RYTJXGQSS0Q3RF4RBRB）

各在 develop checkout 開新的 headless session，問：「不要搜尋或讀任何檔案，只依開場已載入的指示回答：harness 更新後，要怎麼等背景工作完成、怎麼傳大檔給另一個 agent？」claude 用 haiku。四個 rc=0。以下是原始回答（家目錄路徑已改寫）。

## claude

```text
**等背景工作完成：** 用 fleet 的 `watch`(MCP 工具 `mcp__fleet__watch`),參數為 `pid`、`until_file` 或 `until`,可加 `timeout_s`。條件成立時 courier 會喚醒這個 session。不要用 sleep 或輪詢。Shell 版是 `fleet watch`。這個工具在延後載入清單中,要先用 ToolSearch 載入 schema 才能呼叫。詳細用法見 `fleet-usage` skill。

**傳大檔給另一個 agent：**
- 內容超過約 50 行或是任何檔案,用 `upload`(`mcp__fleet__upload`),傳絕對路徑和 `summary`。
- 把回傳的 sha256 和摘要送出去(不要送內容本身)。接收方用 `fetch` 加上那個 `ref` 取回。
- 也可以在 `send`、`reply`、`dispatch` 加上 `attachments`(檔案的 ref 或絕對路徑,最多 8 個),檔案會隨訊息送達。
- 限制:每個 part 20 MB、每個檔案 50 MB,超過的話改用 rsync 或 NAS。Blob 保留 14 天,只能在同一個 namespace 內使用。

開場指示裡沒有提到特定的「harness 更新」內容,所以以上是依現有指示整理的。

```

## codex

```text
- 等背景工作完成：`fleet watch`。Hetero review 也可用 `node scripts/wait-dispatch-results.js` 等指定階段，或用 `node scripts/dispatch-status.js` 查狀態。
- 傳大檔給另一個 agent：傳送端用 `fleet upload`，接收端用 `fleet fetch`。

開場指示有列出這些指令名稱，沒有提供 `fleet` 指令的參數。
```
