### 展開高度、色彩語意與窄寬度降級

- **內容驅動高度（上限 60%、零空白填充）**：展開區高度 = `L1/L2 實際內容列數 + L3 固定列數 + 外框`，隨內容自動伸縮，最高不超過終端機總列數的 **60%**（`Math.floor(rows * 0.6)`）。超出 60% 時啟用頂部錨定捲動視窗與右側 1-cell 捲軸（`cardSplit` 與 `fixedWindow`/`thumbOf`，`mods/live/band.tsx:365-383`、`mods/live/scrollmath.ts`）。**嚴禁空白填充列**：廢除 `BODY_ROWS = 8` 最小高度保底（`shell.ts:20`、`register.ts:1370`）及 `while (rows.length < winRows)` 補空行（`band.tsx:378`、`shell.ts:270`）。
- **色彩與強調（遵循 `mods/CLAUDE.md:7`、`mods/live/design.md`、`mods/live/ui.ts:79-99`）**：
  - **純文字色、無背景色**：僅允許透過 `PALETTE`（`ui.ts:87`）使用 8 個 theme-key 文字色，嚴禁 `backgroundColor` 與 `inverse`（`ui-lint.test.js:133, 241`）。
  - **一色一義**：`attention` (`warning`) = 需操作者處理；`here` (`claude`) = 當前位置／選中項／作用中分頁底線 `━`；`broken` (`error`) = 失敗／卡住／超額；`done` (`success`) = 已完成／已送出；`running` (`suggestion`) = 執行中；`idle` (`inactive`) = 待命／未選／次要外框；`structure` (`subtle`) = 分隔線 `─│` 與收合符號 `▾▸`；`action` (`merged`) = 可按控制項 `[ … ]`、已選標記 `◆` 與檔案連結。
  - **粗體白名單與單格符號**：粗體僅限 `BOLD_USES` 7 處（`ui.ts:89-99`）；所有符號須取自 `GLYPHS`（`ui.ts:65-75`）並通過 `mods/live/glyph-check.js:7-15` 單格寬度驗證。

## 2. 「我問的問題」區域配置規範（Operator Questions Zone in L1）

現行 `recentLines`（`mods/live/tabs.ts:459-483`）與 `groupRecent`（`mods/live/model.ts:1820-1885`，`RECENT_MAX = 3`、`RECENT_COLLAPSED_CHARS = 60`）將最近對話放在 `Now` 分頁最底部的獨立折疊區塊（`SECTION_ORDER.now` 末項，`ui.ts:405, 415`），導致操作者在 PM 面板處理決策卡時，無法同屏追蹤自己向 PM 提出的問題與回覆進度。

1. **版面位置（L1 並排分區，非獨立區塊）**：
   - 「我問的問題」必須作為 **L1 清單層的右側並排分區（L1-Asked Zone）**，直接位於「待決卡片佇列（L1-Queue Zone）」旁，兩區以單格結構線 `│`（`GLYPHS.structure.bandSep`，色票 `PALETTE.structure`）分隔，共用 L1 外框頂底，**嚴禁獨立成上下堆疊的區塊或新分頁**。
2. **資料筆數與欄位格式**：
   - **筆數**：標準寬度（`>= 120` cols）顯示最近 **5 筆**操作者向 PM 發出的實質提問（過濾 `INJECTED_PREFIXES` 與 toolResult，複用 `isRealPrompt` 於 `model.ts:1841-1846`）；窄寬度（`< 120` cols）顯示最近 **3 筆**。
   - **主列格式（每筆 1 列）**：`<狀態符號> <時間> <40字摘要> <狀態詞>`
     - **狀態**：`已回覆` 使用 `✓`（`GLYPHS.state.done`，`PALETTE.done`）；`等回報`（尚無 assistant 非空回覆或 turn 仍在執行）使用 `⋯`（`GLYPHS.state.waiting`，`PALETTE.attention`）。
     - **時間**：呼叫 `ui.clock(ms, nowMs)`（`mods/live/ui.ts:218-223`，當日 `HH:MM`、跨日 `MM-DD`），設為 `dim`。
     - **40 字摘要**：經 `redactSecrets`（`model.ts:1835`）與 `oneLine`（`model.ts:1881`）清理後，以 **40 個字元**為上限截斷並加上 `…`（取代原 `RECENT_COLLAPSED_CHARS = 60`，`model.ts:1821`）。
   - **回覆預覽（最多 2 列，僅 `已回覆` 時繪出）**：
     - 緊接於主列下方，取 assistant 回覆的前 **2 行**非空文字，每行以 `  └ `（`GLYPHS.structure.detail`，`ui.ts:67`）縮排並設為 `dim`，單行截斷不折行。若為 `等回報`，不繪任何預覽列（零空白填充）。

## 5. 宿主限制（Host Constraints）

以下列出 Claude Code 終端機宿主（Host TUI）對 `AbovePrompt`（Band / O4 Shell）與 `Pane` 之硬性限制。設計與實作必須在宿主邊界內運作，不得假設插件可覆寫宿主外框行為：

1. **L3 快速操作列（Quick Row）與宿主輸入框（Prompt Box）之間的空白列**：
   - **原始碼與測試證據**：`mods/live/band.tsx:35-38` 的 `stackRows` 僅回傳 `<Box flexDirection="column">{rows}</Box>`，並未加入任何備用空白列（no spare row）；`mods/live/band.tsx:265-267` 的 `Shell` 將 `key="quick"` 作為回傳陣列的最後一個 `Box`（緊隨 `key="menu"` 之後，由 `mods/live/register.ts:1408` 直接交給 `stackRows`）；且 `mods/live/live.test.ts:7122-7130`（`drawShell`）與 `mods/live/live.test.ts:7398-7399` 皆驗證渲染樹的最後一列即為 `quick` 操作列（含 `送出`、`上一張`、`下一張`、`下一個選單`）。
   - **結論與待辦驗證**：Band 快速列與宿主下方 Prompt 輸入框之間出現的 1 列空白，**係由宿主（Host TUI chrome）自行繪製，而非 `mods/live` 所產生**。*（註：此結論目前係由原始碼與單元測試推導得出，尚未拍攝真實終端機截圖〔real-terminal screenshot not yet taken〕，後續須於實機補拍確認。）*
2. **超出 `maxRows` 時宿主強制開窗並以 `"n more"` 遮蔽 L3 快速列（`mods/live/band.tsx:33-34`、`mods/live/register.ts:1362-1365`、`mods/live/design.md:28`）**：
   - 當 `AbovePrompt` 回傳樹之總列數超過宿主傳入的 `e.props.maxRows` 時，宿主會自行套用內建捲動視窗，並將樹的最後一列（即 L3 `quick` 操作列）藏在宿主的 `"n more"` 提示行後面。因此展開卡總高度必須嚴格 `<= maxRows`（`avail = rows - 6`），絕對不可多畫任何備用列。
3. **視窗外（Off-tree）`Button` 的數字熱鍵 `hotkey` 自動失效（`mods/live/register.ts:1375-1379`）**：
   - 宿主僅對當下實際掛載於渲染樹中的 `Button` 元件攔截 `hotkey`；若長卡捲動導致選項按鈕被裁切出畫面，按 `1–6` 即無反應。因此超高卡片進入 `cardSplit`（`mods/live/band.tsx:362-383`）時，必須將選項按鈕抽離至底部不捲動的固定 `strip`。
4. **宿主打字框僅支援填充（`$.prompt.fill`）而不支援代客送出（`mods/live/register.ts:1341-1347`、`mods/live/live.test.ts:7344-7356`）**：
   - 點擊 `f: 補充／打字` 或 `f: 打字回答` 僅能呼叫 `$.prompt.fill({ text, mode: 'replace' })` 將 `[待決回覆]` 模板填入宿主輸入框，無法亦不得由插件直接觸發 `prompt.submit`，必須由操作者打字後親自按 `Enter` 送出。
5. **`Pane` 跨分頁共用單一宿主捲動偏移（`mods/live/register.ts:1508-1512`）**：
   - 宿主對同一個 `PANE_ID` 僅維持單一 scroll offset；若操作者先在其他分頁向下捲動，切回自繪捲動視窗的「待決」分頁時，宿主的非零 `scroll.offset` 會把底部固定操作列擠出畫面，故每次渲染須由 `hostScrollHome` 呼叫 `$.ui.scroll({ in: PANE_ID, to: 'start' })` 歸零。
6. **宿主無讀取當前焦點之 API（`mods/live/register.ts:1473, 1483-1489`）**：
   - 宿主未提供讀取當前 focus key 的方法（`the host has no call that reads the focus`），故批次答卡與原地灰化後須由插件自存 `decideFocus` 並呼叫 `$.ui.focus` 主動修復焦點。
7. **未掛載 `Raster` 時宿主拒絕 `$.ui.blit`（`mods/live/register.ts:1414-1415`）與 `$.env.get` 字面量限制（`mods/CLAUDE.md:9-11`）**：
   - 下層模組（如 `forge-stats`）之 `Raster` 未掛載於回傳樹時，宿主會以 `{ deny }` 拒絕其 `blit` 繪圖；且 mod loader 強制要求 `$.env.get` 第一參數為字串字面量（由 `ui-lint.test.js` L11 檢查）。
