# Fake MiniMax rows in the real dispatch usage ledger (BL-0429)

`/run/user/<uid>/autopilot/dispatch-usage-202611.jsonl` on <host> (team account) holds 48 rows for runner cc-shim / MiniMax-M3 / account minimax in the week to 2026-11-11. They come in groups of four (2 running, 1 reviewed, 1 no_verdict), with usage none, wall_secs null and no run manifest, at the times full or affected suites ran. The team account has no MiniMax token, so no real call was possible.

Cause: `hooks/tests/hooks-live-state-misc.test.sh` `assert_r79_cc_shim_framing_chro` runs `dispatch-review.sh --runner cc-shim --model MiniMax-M3 --endpoint minimax` twice (reviewed + no_verdict) under `env -u AUTOPILOT_LIVE_DIR`. `scripts/lib/dispatch-usage.js` then appends via `resolveLiveDir()` to `$XDG_RUNTIME_DIR/autopilot/dispatch-usage-YYYYMM.jsonl` (the host ledger). Fixed by pinning `AUTOPILOT_LIVE_DIR` to the suite's `/dev/shm` temp live dir and asserting the rows land there. Found while cross-checking the first quota-provider-sync probe (PM message 01M75H3XZ0).
