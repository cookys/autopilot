## 0. Thesis
llm-playground model intake is where a qualification exam is administered. Intake calls autopilot `scripts/engine-qualify.sh` under the P5 headless contract and commits the schema-2 record itself. llm-playground is the only registry of exam records. The authoritative store is, per workspace, `benchmarks/qualification/<ws>/<record>.json` (one file per record) and `benchmarks/qualification/<ws>/strikes.jsonl`. autopilot keeps local evidence for an exam this install administered, local strikes, a user pin, and a cache of the feed. The P3 outbox and its transport exist and default to off. The historical split (autopilot scorecard plus a hand import, a feed with no speed or cost, a stale cache fetched 2026-09-03) is what P1–P4a already replaced on the publish side; this revision replaces who administers the exam and how a feed row is trusted. Shipped consult result A2/B1 remains: one registry, snapshot-built defaults. C1's old reading (metrics never affect admission) does not.

## 1. KRs
- KR1 one authoritative record store. A headless `engine-qualify` (P5) writes only `--store` and `--raw-dir` and does not touch `~/.autopilot`. An exam administered on an autopilot host still keeps its local evidence on that host. The registry copy is llm-playground's commit.
- KR2 feed carries pass rate, solved/hour and cost (null when unknown) per seat x role.
- KR3 no result or strike lost or duplicated under network, push or CI failure (fault tests).
- KR4 with `qualification_feed.trust=off`, admission is identical to having no feed. With `auto` or `confirm`, only a feed that passed the gate is used, and only under the three invariants: the feed never overwrites local evidence, a local strike always wins and the feed cannot lift it, and a user pin always wins.

## 2. Constraints (verbatim into every dispatch)
- ADR-0001: disclosure, not attestation. No signatures, hash chains, witness receipts; `digest` stays a cache key.
- Admission reads four inputs, in this order: a user pin, local strike records, local evidence, then the feed under `qualification_feed.trust`. Local evidence means a result this install administered itself. It is usable immediately, including when the optional outbox is on and the row is still unacked. The feed never overwrites local evidence, never lifts a local strike, and never beats a pin.
- `qualification_feed.trust` defaults to `auto`. `auto`: a qualification result that passed the gate is used for admission, with no adopt step. `confirm`: a new feed row prompts the user once and is used only after that confirmation, with no adopt command. `off`: admission is identical to having no feed. Speed and cost metrics still only order seats; they do not admit or deny. The old C1 reading (a feed qualification never admits) is withdrawn.
- The gate is the P4a preflight: schema, strict JSON, digest, and 30-day freshness. Any failure is treated as no feed and is reported loudly (non-zero status, a visible error line). A hostile or stale document does not change admission.
- Unknown is null, never 0. Wire numbers are integers: enforced by `type: integer` in the shared schema (current `validate-json-schema.js` accepts a lossless non-integer literal unless the schema says integer).
- Every new check ships a negative control, red before green.
- No dual-read shims (owner rule). Compatibility = v2 is a superset of v1.

## 3. Shared spec (single source)
`schemas/qualification-feed-v2.schema.json` in llm-playground is the only spec. autopilot vendors a byte-identical copy at `schemas/qualification-feed-v2.schema.json` (parity test fails on any diff). Validators: llm-playground `scripts/eval/check_qualification_feed.py` (stdlib; supports type/required/enum/pattern/additionalProperties/minimum/oneOf, tested in `scripts/eval/test_qualification_feed.py`); autopilot `validate-json-schema.js`. Both run the same fixture set in `benchmarks/qualification/fixtures/` (copied into autopilot `hooks/tests/fixtures/`).

### 3.1 Feed document (v2 is a superset of v1)
Discriminator: string `schema` = `model-dyno.qualification-feed.v2` (v1 name pattern kept; the only version key; `schema_version` is not used). All v1 top-level keys, including v1 `strikes[]` with its entry shape, stay byte-unchanged. New top-level: `generated_at` (UTC `...Z`), `producer` (string), `source_revision` (git sha), `seat_metrics[]`, `strike_events[]`. Compatibility test: the current `parseFeed` reads a v2 fixture, results for v1 fields byte-identical.

### 3.2 `seat_metrics[]` entry (additionalProperties false; `kind` discriminates)
- `entry_id` string, sha256 hex of canonical JSON (sorted keys, no whitespace) of [`seat`, `kind`, `instrument_id`, `window_end`]; `window_end` (UTC `...Z`) is a required top-level field of every entry.
- `seat` {engine, model, model_version, runner, role, effort}: strings. No seat hash is published (consumers recompute).
- `kind`: `qualification` or `benchmark_observation`. Required block per kind: qualification => `qualification` only; benchmark_observation => `benchmark` + `speed` + `cost` + `sampling`. Any other block present is invalid (fixture mixing blocks must fail).
- `instrument_id`, `instrument_version`: strings.
- `qualification` {status: qualified|failed|provisional, corpus_version, prompt_config_hash, administered_at, record_id, record_id_basis, supersedes: record_id or null}; `expires` advisory.
- `benchmark` {n_tasks (per trial), n_trials (repeated runs of the task set), n_attempts (every execution incl. retries, >= n_tasks*n_trials), n_pass and n_timeout (attempts), pass_rate_permille = round-half-up(1000*n_pass/n_attempts), ci_method `wilson`, ci_level_permille 950, ci_low_permille, ci_high_permille}. Every ratio is null when its denominator is 0.
- `speed` {solved_per_hour_milli = round-half-up(n_pass x 3.6e6 / wall_s_total), wall_s_total = summed wall seconds of ALL attempts; tasks_per_hour_milli = same with completed attempts; median_wall_ms (per task, integer ms); concurrency; speed_basis = `window_start..window_end` text}. Zero denominator => null.
- `cost` {usd_per_solved_micro, usd_per_task_micro, cost_total_micro, cost_coverage_permille (attempts with known cost), cost_basis billed|estimated|subscription|unknown, pricing_version}. Unknown => null with coverage 0; subscription => null; null sorts last.
- `sampling` {window_start, low_n (n_trials < 5)}. Units: `_permille` 1/1000, `_milli` 1/1000 unit, `_micro` 1e-6 USD, `_ms` ms; every derived integer rounds half-up.
- `join` {board_cell, board_join mapped|unmapped, identity_map_version}: unmapped rows are shown, never ranked. No map hash is published.
- `origin_host_class` only (`local-gpu`|`cloud-api`). `evidence_ref`: relative path inside the registry repo, never a URL.
Example (benchmark_observation, one entry) is `fixtures/seat-metrics-benchmark.valid.json`, written in P1 before the producer code.

### 3.3 `strikes[]`
`strike_events[]` entry (v1 `strikes[]` untouched) {strike_id, strike_seq (integer, assigned by the registry at commit, monotonic per seat; the sender never supplies it), seat, effort or null, reason, lifted_by: strike_id string or null}. Disclosure only: for autopilot it is report and cross-host reference data. No trust mode writes, overwrites, or lifts a local strike; `lifted_by` is informational. A feed that names a lift of a local strike is rejected for that strike. Local evidence wins over any feed row for the same administration.

### 3.4 Keys
- `record_id` = sha256 of canonical JSON of [`producer`, `transcript_hash`, `seat` (6 fields), `corpus_version`, `administered_at`]; `record_id_basis` = `v1:` + that field list. `engine-qualify`, the importer and the ingest share one implementation per language and a cross-language parity fixture; the importer must produce the same id for the same administration (P1 test).
- `strike_id` = sha256 of canonical JSON of [`seat`, `effort`, `reason`, `administered_at` of the failing record, that `record_id`].
- Same id with different payload bytes = conflict: rejected loudly, never merged.

## 4. Write path
Primary path, the one intake uses: llm-playground calls `scripts/engine-qualify.sh <role>` with `--seat-file`, `--store`, `--raw-dir`, and `--emit-record`. The process writes only those two directories, exits with a defined code, and does not touch `~/.autopilot`. `--emit-record` prints one schema-2 record. llm-playground imports it with `ingest-qualification-record.py` (idempotent on `record_id`; the same id with different bytes is `[conflict]`, nothing written) and commits that file itself. There is no bot PR on this path.

Optional path, default off: an exam that was administered on an autopilot host, not by intake. The host keeps local evidence. llm-playground's importer pulls that host's store and commits the record itself. The P3 outbox (`~/.autopilot/qualification-outbox/outbox.jsonl`, append-only, one line per append under `flock`, events `enqueued|sent|acked|retired`) and its flush transport stay available only when that host enables them. Transport is retained for a host that cannot be pulled. It is not how intake writes the registry. A feed refresh never alters a local strike, acked or not. Failpoints `AUTOPILOT_OUTBOX_FAILPOINT=<after-enqueue|after-send|before-ack|after-ack>` cover the optional path only.

## 5. Read side
- Cache `~/.autopilot/qualification-feeds/` (content-addressed); `current.json` already has `fetched_at`; add `generated_at` (producer age). `list --json`, `engine-scorecard.js status` and adopt provenance report `fetch_age_s` and `producer_age_s`; missing or future timestamps are labelled `unknown`/`clock-skew`. Past `qualification_feed.max_age_s` (7 d) either age => warn, still serve; past 90 d label `expired-advisory`, still serve. Never blocks.
- Offline: pins, local strikes, and local evidence still admit. With `trust=off`, or with no cached feed, admission matches the no-feed case. With `auto` or `confirm`, a cached feed is used only when it still passes the gate, including the 30-day freshness check; otherwise it counts as no feed and the miss is reported loudly. Offline never denies a seat that local evidence or a pin already admits, and it never lifts a local strike.
- B1 (scheduled in P4a): `references/official-qualification-defaults.json` is regenerated by `build-qualification-defaults.js --from-snapshot <feed>`, recording snapshot digest and `generated_at` in `official-qualification-defaults.recipe.json`; `--check` stays byte-identical. ## Appendix A. Cross-repo alignment (P1 review x P2 reader, 2026-10-16)
- `record_id`: the legacy basis is kept, with an idempotency secondary key. Only rows carrying `transcript_hash` have a recomputable `v1:` id. A legacy row keeps its `evidence_id` / `row_digest` id and is never recomputed. The secondary key is compared only when BOTH sides carry `administered_at`; a legacy row against a new row compares by `evidence_id`.
- Ack on the primary path is llm-playground's own commit of the ingested record. The optional P3 transport (a host that cannot be pulled) is off by default. Intake does not use a bot PR.
- `strike_events[]` live in the metrics document and a separate registry file `strike-events.jsonl`, apart from the autopilot-format `strikes.jsonl`. They are disclosure only (section 3.3); `reconcileStrikeDisclosure` returns local strikes untouched.
- `effort` is a token or JSON null; null is not `default` (they hash to different seats and never match each other).
- Reader dedupe: benchmark entries are collapsed by `(board_cell, instrument_id, window_end)` before use, because one board cell appears once per seat mapping to it. Unmapped rows are never ranked. Unknown speed, pass rate or cost is `null` and sorts after every known value.
- Authority (section 2 and 5, as revised 2026-10-19): a pin, a local strike, and local evidence outrank the feed. With `trust=auto` or `confirm`, a gate-passed feed qualification is used for admission and does not require a local row or an adopt. It is not local evidence and never overwrites local evidence.
