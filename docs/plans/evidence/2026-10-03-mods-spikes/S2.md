## Key fact (the one that matters): path semantics
Types doc comments (types/claude-code.d.ts, `fs: {`, ~line 3015):
- `read`: "@param path relative to the working directory, or absolute"; "Rejects when missing, or over 4 MiB"
- `write`: "@param path relative to the working directory, or absolute"
- `list`: "@param path the directory's path; absent, the working directory"
- `stat`: "@param path relative to the working directory, or absolute"; `{resolve:true}` adds `realPath`
- `env.get`: "`name` must be a string literal; `claude plugin validate` lists the names your module reads and writes."
Observed (cwd = root = $WORK/proj/sub, terminal -p): a relative path resolves against $.session.cwd() (`marker.txt` -> sub/marker.txt; `../marker.txt` -> proj/marker.txt); absolute paths work and **there is NO project-root confinement on $.fs.read/list/stat/exists/write**: `../../outside-marker.txt` and `$WORK/outside-marker.txt` and `/etc/hostname` all read fine, `$.fs.list` of a dir outside root worked, and `$.fs.write` to an absolute path outside root succeeded (`s2-write-outside.txt` created). `~` is NOT expanded: `~/.autopilot/live-pointer.json` became `<cwd>/~/.autopilot/live-pointer.json` -> ENOENT. So the pointer route must build absolute paths from $.env.get("HOME") (plan §2.8) — it works.
