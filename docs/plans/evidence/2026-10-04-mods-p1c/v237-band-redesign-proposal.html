現在不能發 v2.37.0

若照目前的程式落地：五個結論詞裡，「要你決定」和「完成待驗收」永遠不會亮；phase 和進度在所有模式下都是空的；你最常用的 dev-flow 模式，狀態列只會顯示 no project。這台機器上這套管道從來沒有產生過一份真實的 review 頁。

原因：讀取端做好了，寫入端不存在

每個欄位都要走四段。斷掉的那一段標紅框。

要你決定寫入端：沒有任何流程寫「待決定」檔；轉交端：watcher 寫死傳 null
進度 %／n done*engine 有算（藏在 work-order 檔裡），但沒人取出來，watcher 寫死傳 null
phaseengine 有即時階段（同一個 work-order 檔），沒人取；dev-flow 的階段只存在文字裡
完成待驗收依賴驗收 receipt，而它的輸入檔全 repo 沒有人寫（這也卡住 finish-flow，是既有問題）
dev-flow 有狀態列只有 /l3–/l6 會啟動 watcher，dev-flow 從不啟動
疑似卡住／進行中派工紀錄 → watcher → 狀態列，這條真的通
花費、context既有 hook 和你的 status line 在寫，這條通

另外：review 頁在沒有來源時會寫「知會：目前沒有待你決定的事項」，這句話會讓人誤以為沒事。要改。

設計原則（三條）

  • 只顯示有寫入端在運作的欄位。做不出寫入端的欄位，這一版直接拿掉，不留空格假裝會有。
  • 寫入端優先，而且只用「機制」。寫入端用 hook 或 script 自動寫，不靠在 SKILL.md 裡叫我記得去呼叫（那種改法依規則要先有 eval 證據，而且會忘）。
  • 發版門檻是真機實跑。在你的 ssh＋tmux 環境，各模式真的跑一次，狀態列每一格都看到真值，才算通過。測試套件裡的假資料不算。

這一版不做（各自已有追蹤）

  • 代你決定（P5）：沒有寫入端，順序是寫入 → 發佈 → 顯示。
  • 驗收輸入檔的產生者：既有缺口，也卡住 finish-flow 收尾，另案處理。
  • dev-flow 明確的階段（L-1…L-5）：要改 SKILL.md，需要 eval 證據。這一版先用「目前任務名稱」頂替。
  • 臨時派工每次各自成一頁：review 頁會碎成很多頁，後續處理。

做事的順序

  1. 把這份設計寫進計畫（P1c／P1d 改版），跑一輪計畫審查。
  2. spike：等你回應的 hook 事件、Task 工具 hook 拿得到什麼、task 工具有沒有開。結果不如預期就回頭改設計，不硬做。
  3. 實作：取出器、三個新 hook、狀態列改讀、review 頁誠實化。
  4. 真機驗收：你的 ssh＋tmux，各模式各跑一次，截下狀態列文字。
  5. 落地 v2.37.0。

需要你決定

  1. 方向同意嗎？先接寫入端、拿掉沒有來源的欄位、真機實跑才發版。
  2. 三個新 hook 預設開啟可以嗎？Task 工具、等你回應、自動啟動 watcher。各自有關閉旋鈕。
  3. 計畫審查要再跑一輪嗎？原計畫已經用完兩代審查。這次改動是新設計、不是小修，我建議當成 P1c／P1d 的重新規劃，跑一輪新的審查。
  4. dev-flow 的 phase 先用「目前任務名稱」可以嗎？還是你要等真正的 L-1…L-5 寫入端（要先做 eval）？
