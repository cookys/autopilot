## A. WATCHVER — a watcher must not outlive a plugin update
Evidence: df3-running FAILED because the project watcher started before the GATEFIX2 update kept running old code (`--idle-exit 3600`); killing it let autostart respawn a current one. Fix: at start the watcher records a code fingerprint (sha256 of its own module files: `src/status/*.js` it requires + `scripts/render-review-page.js` + `.claude-plugin/plugin.json` version — keep it cheap: stat mtimes+sizes, hash only when they change); every tick it re-checks; on change it exits cleanly (release its lock, log `code changed, exiting`) so the next UserPromptSubmit/SessionStart autostart starts a current one. Tests: fingerprint unchanged → keeps running; a touched module → exits within one tick and releases the lock; autostart then spawns a new one (existing autostart tests).
