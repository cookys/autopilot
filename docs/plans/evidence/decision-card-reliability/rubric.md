# Decision card reliability plan review rubric

- R1: [重開防呆] 計畫是否明確定義已答卡的比對範圍、拒絕行為、原答案回顯，以及繞過負控制？
- R2: [請求轉送] 計畫是否說明 from_request 的來源、原請求方的定位方式、成功紀錄與失敗狀態，足以實作及驗證？
- R3: [故障分診] 計畫是否可獨立區分面板不可見與派送失敗，並涵蓋兩者同時故障的驗收？
- R4: [跨系統契約] 119 筆未送達的介面需求是否定義欄位、分類、驗證方式、交付對象及本 repo 邊界？
- R5: [回歸證據] 四張重問卡與五張 verify_failed 的來源、fixture 取得方式、斷言及負控制是否足以驗證真實案例？
- R6: [執行依賴] 子工作、共用檔案、依賴與里程碑是否一致且足以安全執行？
- R7: [安全邊界] 計畫是否保留既有授權、目標環境閘門與卡片語意，並明確排除 daemon 和對方 repo 修復？
