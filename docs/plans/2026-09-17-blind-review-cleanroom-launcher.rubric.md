# Rubric — 2026-09-17-blind-review-cleanroom-launcher.md

> Source plan: docs/plans/2026-09-17-blind-review-cleanroom-launcher.md

R1: Under blind mode every runner resolves to exactly one seat tier from a single table in `dispatch-review.sh`: prompt-only runners run exactly as before, runners with no enforceable profile are refused with the unchanged message, and the tool-capable runner is routed to the isolation launcher; outside blind mode no runner's behaviour changes and the non-blind tool-capable path keeps its read-only sandbox byte-for-byte.
R2: A cleanroom seat cannot start without its preconditions — a review packet on disk, a working isolation runtime, a resolvable runner binary directory and a credential file — and each missing precondition refuses with exit 2 and a named message before any model process exists; a launcher failure or timeout is a `no_verdict` carrying the exit code, never a parsed verdict.
R3: Inside the boundary a seat can read only the packet tree (byte-equal), its own writable throwaway HOME holding one copied credential and a launcher-written minimal config, the runtime and TLS/DNS; the host repository, the operator HOME and credentials, the packet's host path, host `/tmp`, `/etc/hostname`, a sibling seat and the host-side launch argv are all unreadable, and nothing the seat writes survives outside its seat root, which is removed on exit.
R4: The launcher is one script with an argv-only contract, a single supported profile in this cut, a `--preflight` mode that exercises the identical boundary with a deterministic probe and exits 0 only when every caller-named host path is denied and the argv is clean (2 when the runtime is missing, 3 naming the first readable path), a JSON launch line appended to the seat's raw log, and passthrough of the wall-clock timeout exit code.
R5: Tests are RED-first and honest about the host — the portable suite pins the tier gate, the precondition order, the launcher argument shape and the parser/raw-log wiring with stubs only; the isolation suite drives the REAL launcher with a hostile stub binary, is gated on an explicit host variable, prints a skip only when that variable is unset, and when set fails (never skips) on a missing runtime or a readable denied path; every change-pinning assertion records the observed base message.
R6: Scope integrity — `git diff --name-only <base> HEAD` ⊆ plan §2.5 plus committed plan/mission docs; `src/**`, `schemas/**`, `bin/autopilot.js`, the resolver and the qualification provider are byte-identical to base; the new launcher and suite are `test -x`; no new CLI flag; the new script is registered in the scripts inventory and the CLAUDE.md script list.
R7: Every command in plan §4.1 exits 0 at the candidate, and the same set was green at base before sealing (detached checkout; the isolation suite under its host variable on this host).
R8: Docs — `references/blind-dispatch.md` gains the cleanroom-tier section (tiers, boundary, what is and is not proven this cut, pointer to the intake/resolver half) with its mirror in sync; the BACKLOG redesign row Context is the plan §2 string within 240 bytes with Status `open`; the plan states plainly that no live tool-capable verdict is claimed while the provider quota is exhausted.
