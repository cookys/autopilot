# Live TUI — i18n plan (design proposal)

## Today
User-visible strings are literals scattered over `model.ts` (the `VERDICT` words are zh: 要你決定 / 疑似卡住 / 完成待驗收 / 進行中 / 待命; `TAB_LABEL`; legend lines; `no data · …`; `session cost as of …`; pane labels `position`, `unit`, …), `pane.tsx` (`started`, `elapsed`, `probe … ago`, the bilingual caption `execution status, not progress (執行狀態，不是進度)`), `band.tsx` and `register.ts` (waiting / unreadable reasons, header). The band is zh, the panel is en. There is no English source locale yet.

## String table
- One id per user-visible string, dotted by surface: `band.verdict.needs_you`, `band.qc.owed`, `tab.now`, `now.section.where`, `now.hands_running`, `hygiene.auto_reap`, `nodata.stage`, …
- Placeholders are `{name}`; code substitutes numbers, ids, paths and commands. Translated fragments are never concatenated (word order differs: zh puts `前` after the time, en puts `ago` — both live inside the one string).
- Plurals: en needs `x.one` / `x.other` only where a noun is counted (`1 worktree` / `3 worktrees`); zh repeats the same text for both. No ICU dependency (the mod is built-ins only).
- Files: `mods/live/locales/en.json` (source of truth, complete) and `mods/live/locales/zh-TW.json`. A small `t(id, vars)` in `mods/live/i18n.ts`: active locale, else en, else the id itself (visible and greppable, never throws).
- Loading: a hooks module can import only its own plugin files, and `import()` is refused, so either generate `locales.ts` from the JSON in the repo's sync step (the JSON stays the editable source; preferred), or read the JSON once per load with `$.fs` in `register.ts` and pass the table down. `model.ts` stays pure: it receives `t` as a parameter, as it already receives `nowMs`, so tests call `layoutBand` with a fixed `t`. **[unverified]** whether `.json` files are importable from a hooks module (the manifest lists `.ts .tsx .jsx .js .mjs .cjs .mts .cts` as loadable), hence the generated `.ts`.
- A parity test enforces: same id set in both files, same placeholder set per id, every id used in code exists in en, `displayWidth(label) <= 12` for key-column labels.

## Locale selection
1. `~/.autopilot/config.json` `ui.locale` = `"en"` | `"zh-TW"` | `"auto"` (default `auto`). Read like `register.ts` already reads that file for the cost-fuse mode. Highest priority.
2. `AUTOPILOT_LOCALE` env for tests and one-offs.
3. `auto` follows Claude Code's own language setting. This machine has `"language": "正體中文台灣用語"` in `~/.claude/settings.json`. The mod API exposes the `/config` rows through `$.config.list()`; **[unverified]** whether a `language` row exists. Otherwise read `settings.json` with `$.fs` (user and project scope). The value is free text, so map by pattern: contains `正體|繁體|台灣|zh-TW|zh-Hant|Traditional` -> `zh-TW`; anything else -> `en`. No other Chinese variant is claimed until someone ships it.
4. Last fallback: `LANG` / `LC_ALL` (`zh_TW*` -> zh-TW) through `$.env.get` (declared in the module's env list), then `en`.
Resolved once per tick so a config change takes effect without a reload.

## Width handling (CJK)
- Layout already measures `displayWidth` (East Asian Wide = 2) in `layoutBand` and the clip helper. Added rules: (a) every fixed-width column pads by display width (`String.padEnd` is wrong for CJK; the mockup's `pad` does it right); (b) key-column labels are budgeted in cells (12): zh up to 6 characters, en up to 12; (c) the band width table runs on the translated text, so zh may keep a slot that en drops; the table is a cell budget, not a locale rule; (d) never clip inside a data value (path, id, sha): clip the label, not the datum.
- The mockup renders every character in a 1- or 2-cell box to prove the alignment; the first render showed that wide characters in a fallback font silently break column alignment unless the cell width is fixed, so the real pane must keep padding in cells, never in `ch`-like font-relative units (only a concern for the HTML mockup, not the terminal).
- Ambiguous-width glyphs (`⚑ ◐ ▲ ▰`) stay 1 cell as today; no emoji (2 cells, ignore colour) are introduced.

## What stays untranslated
Glyphs; numbers and units (`$60`, `3m`, `2.4 GB`, `R2`, `U2`, `k/N`); stage node ids and run ids; role names that are identifiers (`hands`, `reviewer`, `foreman`); engine / model ids; family names (Anthropic, OpenAI, xAI); every command string (`git …`, `autopilot status runs --watch`); paths and shas; technical terms kept in English per the zh-TW copy convention (gate, review, diff, commit, artifact, worktree, branch, depth-0, hands, QC). `QC` stays `QC`.

## zh-TW copy rules applied (memory `zh-tw-copy-conventions`; `narrative-freeze-anchor` was read for vocabulary)
- Technical terms stay English with a half-width space against CJK (`3 個 worktree 要你處理`, `push 前還欠 QC 證據`); gate is not translated to 閘 (`Review gate`).
- Sentences have a subject or a clear object, never a bare imperative: `目前沒有事要你處理`, `這是執行狀態，不是進度`.
- Canonical words reused: 要你決定 / 疑似卡住 / 完成待驗收 / 進行中 / 待命 (the existing, already owner-reviewed band words, kept verbatim), 工頭 for the narrative name and `foreman` as identifier, 紅線, 派工.
- Taiwan usage: 設定 (not 設置), 回報 (not 反饋), 檔案 (not 文件), 預設 (not 默認), 專案, 資料. Time: `3 分鐘`, `已進行 38 分鐘`; `前` after a time.
- Terse by design (pane is 75-95 cells): 2-char tab labels (現況 派工 花費 清理 圖例).
- Open wording choices for the owner: tab `清理` vs `殘留` (Hygiene / residue); `花費` vs `用量`; whether `Review` stays English in the tab strip (the mockup keeps it English per the keep-technical-terms rule; 審查 would also read well).
