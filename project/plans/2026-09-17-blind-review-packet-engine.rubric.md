# Rubric — 2026-09-17-blind-review-packet-engine.md

> Source plan: docs/plans/2026-09-17-blind-review-packet-engine.md

R1: Every managed review dispatch is packet-backed — each campaign `performReview` and terminal-site review calls the review dispatcher with `blindDiscovery: true` and `packet = { repo, baseSha, candidateSha }` where `(baseSha, candidateSha)` is exactly the `(base, commit)` pair the diff provider was given for that same review and `repo` is the loop repository; a non-blind direct `reviewDiff` carries no `packet` key; a caller-supplied `reviewOptions.packet` never survives.
R2: Packet identity is surfaced without changing anything else — `reviewDiff` returns `packet` (the dispatcher's packet object) on its success return only when its `packet_hash` is 64 lower-case hex, otherwise the key is absent; `performReview` returns `packet_hash` only when a packet was present (key absent otherwise, never `null`); `review_digest`, ledger entries, campaign events and every failure return keep their base shape.
R3: The seat receipt carries `packet_hash` inside the digested body only for a reviewed seat whose outcome has a 64-hex hash; a failed seat never carries it; when the dispatcher returned no packet the receipt is byte-identical to the base receipt (all eight receipt-building suites pass untouched).
R4: The panel refuses inconsistency independently at two layers — the engine returns `reviewed: false` when reviewed seats mix presence/absence of the packet hash or hold two distinct values, adding no new key to the panel object; the composition validator, from the receipt alone, distinguishes mixed presence and value mismatch by two stable reason codes, files a malformed (non-64-lower-hex) or misplaced (non-reviewed seat) value under the existing metadata-incomplete code, fails a tampered value on the receipt digest, and passes an all-absent legacy receipt; optional seat keys have one allow-list constant.
R5: Schema parity — `schemas/implementation-campaign-receipt.schema.json` `$defs/finalPanelSeat` accepts an optional 64-hex `packet_hash`, rejects a non-hex one and still rejects any unknown key with `additionalProperties: false`; the codex mirror of every changed file is byte-identical (`sync-codex-plugin-skills.sh --check`).
R6: Tests are RED-first and non-vacuous — every change-pinning assertion records the observed base message (`RED at base bee8da3d: …`), preservation guards are labelled, the seat-receipt digest is re-computed in the test from the body, the two-seat panel case reuses the routing suite's real-`performReview` proof-panel fixture with per-call configurable stub packet hashes, and no engine suite builds a real packet or runs a real reviewer.
R7: Scope integrity — `git diff --name-only bee8da3d HEAD` ⊆ plan §2.5 plus committed plan/mission docs; `scripts/**`, `bin/autopilot.js`, `src/runners/**`, `dispatch-review.sh`, the intake predicate and the resolver are byte-identical to `bee8da3d`; no new CLI flag, resolver field, config knob, ledger entry or event type; no file is created.
R8: Every command listed in plan §4 `no-regression` passes at the candidate, and each was green at the base commit before sealing.
R9: Docs — `references/blind-dispatch.md` "Packet blinding" section gains the engine-wiring paragraph (packet-backed managed reviews, optional seat `packet_hash`, mixed/mismatch rules, pointer to cut 1b) with its mirror in sync; the BACKLOG redesign row's Context is the plan §2 string within 240 bytes with Status `open`.
