# Plan — Codex-native lifecycle enforcement

## 0. Context / thesis

The 2026-08-05 Codex controller run did not enter the repository's existing dev-flow before
authoring Mission/control artifacts. It treated unavailable Claude-only orchestration primitives as
permission to improvise at depth 0. The result was structurally plausible work, but the implementer
was never dispatched and the user spent hours waiting on controller-authored work orders.

This is a transport and enforcement gap, not a reason to invent another tracker. The repository
already has the authorities that matter:

- `scripts/session-mode.js` records the chosen controller level and seals Mission routing admission.
- managed `engine implement-review` requires a campaign contract and binds Mission/campaign state.
- `scripts/dispatch-hetero.sh` validates active managed markers against the sealed campaign.
- `hooks/orchestrator-edit-gate.js` already contains a tested decision core for prohibiting depth-0
  product edits in managed sessions, but it is Claude-hook-only, opt-in, and fail-open when the
  marker is absent.

The missing pieces are visible in the current tree:

- `platforms/codex/plugin/skills/*/SKILL.md` is generated byte-for-byte from canonical skill bodies,
  so Codex receives normative `TaskCreate`, `TaskStop`, native `Agent`, and `subagent_type`
  instructions it cannot execute.
- `platforms/codex/README.md` acknowledges that mismatch and defers a future split.
- the Codex production package declares only `PostCompact`; general blocking `PreToolUse` behavior
  has not been live-proven.
- managed dispatch checks an active marker when one exists, but absence is not itself a rejection.

The fix is one bounded chain: project an explicit Codex lifecycle adapter into the affected package
skills, make the existing managed effect path fail closed without its existing session/Mission
authority, and add a Codex pre-effect hook only after a real binary proves the required blocking
contract. A real adversarial Codex run is the terminal oracle. Other controller platforms keep
their current instructions and workflows.

## 1. Problem

Codex currently has enough repository and CLI authority to behave as a depth-0 controller, but its
installed Autopilot payload does not give it executable equivalents for the lifecycle forcing
functions described by the canonical Claude-oriented skill bodies. Because the shared CLI also
permits a managed dispatch to reach preflight without requiring the existing session marker to be
present, instruction drift can become real branch/worktree/model effects.

The current package smoke test proves only that `autopilot:dev-flow` is visible in model context. It
does not prove that Codex enters dev-flow, refuses depth-0 implementation under `/l4`–`/l6`, or stops
before effect when lifecycle authority is absent.

## 2. OKR / KRs

**Objective:** A Codex controller cannot turn a managed Autopilot request into depth-0 substance or
external execution unless it first enters the repository's existing lifecycle authority.

- **KR1 — executable instructions:** every affected Codex-packaged lifecycle/front-door skill starts
  with one generated Codex adapter that names exact supported replacements and explicitly forbids
  imitation or hand-authored substitution for unavailable Claude tools.
- **KR2 — zero-spend fail-close:** a managed implementation campaign with an absent, expired,
  malformed, wrong-repository, wrong-level, or Mission-mismatched session marker terminates before
  provider readiness, worktree/branch creation, dispatcher invocation, or model spend.
- **KR3 — depth-0 separation:** in a live Codex `/l4`–`/l6` session, direct controller mutation is
  rejected while the external managed implementer path remains usable; `/l3` inline work retains its
  existing semantics.
- **KR4 — behavioral proof:** an opt-in real-Codex adversarial test asks the controller to skip
  dev-flow and implement directly. The test passes only when effect sentinels remain zero and the
  transcript plus machine receipt show the named lifecycle rejection or canonical managed path.
- **KR5 — no collateral process:** no new task tracker, work-order authority, Mission graph format,
  or human gate is introduced, and Claude/OpenCode/Antigravity/Grok/Kimi behavior is unchanged.

## 2.5 Global Constraints (copied verbatim into every dispatch)

- Reuse `session-mode` plus Mission/campaign contracts as the only lifecycle authority; DO NOT create a parallel receipt, tracker, ticket, or graph system.
- A missing or invalid managed-session marker is a hard pre-effect rejection with `dispatcher_called:false`, `model_calls:0`, `mutation_attempts:0`, and `resources_created:0`.
- Canonical skill bodies remain authoritative for non-Codex packages; Codex differences are deterministic generated projections, never hand-edited generated payload files.
- No Codex blocking-hook claim may ship without a committed receipt from the real installed Codex binary proving the exact event, matcher, payload identity, exit behavior, and a broken-control denial.
- `/l4`, `/l5`, and `/l6` prohibit depth-0 substance; an unavailable host primitive is an escalation condition, never permission for the controller to implement or author substitute work orders.
- Source-plan headings, tests, review seats, repairs, and doc sync are gates inside the four deliverables below; they MUST NOT become extra deliverables, phases, tickets, branches, or sessions.
- Review is change-only: reviewers receive the plan/rubric or the candidate diff, not an unrestricted repository-wide review request.

## 2.6 Change-policy decisions

- **Compatibility impact:** `authorized-breaking`. Managed campaign callers that omit a valid active
  `session-mode` marker will now be rejected. This is intentional: there is no backward compatibility
  requirement, and the omitted marker is exactly the unsafe path. Normal front doors already create
  the marker; tests and direct managed callers must use the canonical entry path. Record the break in
  `docs/CHANGELOG.md`, update help text, and remove any wording that advertises marker absence as a
  supported managed mode. Rollback is a revert of the enforcement commit, not a permissive flag.
- **Dependency decision:** `none`. Existing Node.js, shell, session-mode, Mission, campaign, and hook
  infrastructure are sufficient. Do not add a shell parser or a Markdown transformation library; the
  Codex adapter is a fixed generated prefix and shell-mediated effect coverage is determined by the
  live hook capability proof rather than guessed parsing.

## 4. Bounded deliverable DAG

The execution graph has exactly four deliverables. `D1 → D4`, `D2 → D4`, and `D3 → D4`; D2 and D3
may run in parallel after intake. No source-plan subsection may be expanded into another tracker row.

| ID | Deliverable | Size | Depends on | Acceptance command / evidence | Resource reservation | Gate-attempt budget |
|---|---|---:|---|---|---|---:|
| D1 | Prove the Codex pre-effect contract | Fix | — | opt-in real-binary driver emits a sealed capability receipt plus a denial control | 1 real Codex session, ≤2 model calls, ≤15 min | 2 |
| D2 | Generate Codex-native lifecycle skill projections | L | — | package test proves exact adapter + unchanged canonical tail for seven named skills | no external model; ≤30 changed canonical files including mirrors/tests/docs | 2 |
| D3 | Require existing session/Mission authority before managed effects | L | — | deterministic matrix proves zero effects for absent/stale/corrupt/mismatched markers and one canonical happy path | no external model; ≤30 min test wall time | 2 |

### D1 — Prove the Codex pre-effect contract

Run the repository's disposable Codex hook-probe package against the installed `codex` binary. Add a
one-shot driver that creates an isolated config/data root and temporary Git repository, installs the
probe, and records only the fields needed for this contract:

1. the actual pre-tool event name and matcher that fire for Codex's direct file-mutation path;
2. whether the payload provides stable `cwd`, `tool_name`, and session identity;
3. the exact non-zero exit and/or structured stdout response that prevents the target mutation;
4. a positive control where a zero-exit hook permits the same mutation; and
5. a broken-adapter control where no sentinel mutation occurs and the CLI exits non-zero.

The receipt must include the Codex version, installed plugin manifest digest, probe adapter digest,
transcript digest, effect-sentinel counts, and exact verdict. Raw prompts, credentials, and arbitrary
tool inputs are not retained.

If the real binary cannot prove blocking for the relevant mutation path, do not add a production
`PreToolUse` hook and do not claim depth-0 enforcement. D2 and D3 may still ship, but D4 is terminally
blocked with the evidence receipt and one Board escalation. Do not replace the missing host capability
with shell-regex guessing, PostToolUse rollback, prose, or another controller-authored work order.

**Done when:** the same real-binary fixture is green for allow, red for deny, and red for a deliberately
broken adapter, with sentinel counts proving the hook—not model prose—caused the outcome.

### D2 — Generate Codex-native lifecycle skill projections

Create one Codex adapter prefix and have the existing sync script prepend it to exactly these generated
skill copies: `dev-flow`, `ceo-agent`, `l3`, `l4`, `l5`, `l6`, and `finish-flow`.

The prefix is normative and explicitly overrides later canonical host-specific spellings. It must:

- map lifecycle entry to `node <plugin>/scripts/session-mode.js set ...` and require its READY output
  before any write, branch, worktree, runner, or model effect;
- map managed implementation to the existing Mission admission → sealed campaign →
  `engine implement-review` route;
- state that `TaskCreate`, `TaskUpdate`, `TaskStop`, native `Agent`, and `subagent_type` are unavailable
  in this package and MUST NOT be imitated with ad-hoc Markdown tickets, inline implementation, a new
  branch/session, or a replacement graph;
- require attachment/resume of the same engine/campaign lineage for repair; and
- stop with the existing precondition/abort receipt when an exact mapping is unavailable.

The generator must fail loudly when a named source skill disappears, the prefix marker is duplicated,
or a generated file's canonical tail differs from its source. Do not regex-rewrite prose inside the
canonical skill body and do not maintain seven full forks.

Tests inspect the installed package, not only the source tree. They assert one adapter marker, exact
adapter digest, exact canonical-tail digest, and no README claim that Codex supplies Claude tools.

**Done when:** package sync/check is deterministic, canonical non-Codex skill bytes are unchanged, and
the installed Codex package exposes the executable override before any incompatible canonical wording.

### D3 — Require existing session/Mission authority before managed effects

Promote the current active-marker validation into a mandatory managed-campaign precondition. Export a
strict validator from `scripts/session-mode.js` and invoke it before provider readiness, roster
resolution that can probe a provider, campaign resource creation, and dispatch. Bind the marker to the
current Git common-dir, effective level, TTL, exact Mission policy/graph/source digests, and the sealed
campaign projection already checked by `verifyMissionRoutingProjection`.

Use one rejection contract for all entry points:

```json
{
  "status": "blocked",
  "phase": "dev_flow_admission",
  "rejection_code": "DEV_FLOW_ADMISSION_REQUIRED_OR_STALE",
  "dispatcher_called": false,
  "model_calls": 0,
  "mutation_attempts": 0,
  "resources_created": 0
}
```

The reason field distinguishes absent, expired, malformed, repository mismatch, level mismatch, and
Mission projection mismatch. The rejection must not mint a marker, repair a graph, create a branch or
worktree, select a new model, or open a new generation. The canonical recovery is to run the existing
front-door/session-mode admission in the same lineage and resume.

The deterministic matrix stubs every downstream effect seam and asserts all counters remain zero. The
positive control creates a real session marker through `session-mode.js set`, uses an existing sealed
campaign fixture, and proves the same implementation path reaches the dispatcher. Update direct tests
and fixtures to enter through that canonical path; do not add a legacy bypass flag.

**Done when:** all invalid-marker classes stop at the same pre-effect boundary with zero counters and
the canonical marker/campaign path still reaches exactly one implementation dispatch.

### D4 — Wire only proven Codex enforcement and prove end to end

If and only if D1 is READY, add a Codex production pre-effect adapter using the exact live-proven event,
matcher, payload fields, and denial response. Reuse `orchestrator-edit-gate-lib.js`; do not import the
Claude wrapper or its opt-in/fail-open policy.

Codex policy:

- no active valid marker: deny direct repository mutation and return `DEV_FLOW_ENTRY_REQUIRED`;
- active `/l3`: preserve inline implementation;
- active `/l4`, `/l5`, or `/l6`: deny all depth-0 direct repository mutation; managed external
  implementers operate in their own CLI worktrees and do not traverse this controller hook;
- corrupt, ambiguous, expired, or wrong-repository marker: deny, never silently treat it as absent;
- non-repository and read-only activity: no-op; and
- shell/exec behavior is covered only to the extent D1 proves an exact enforceable tool boundary. No
  arbitrary command-string parser or unsupported parity claim is allowed.

Extend the package manifest and its description only for the capability actually proved. Keep the
existing `PostCompact` adapter unchanged and isolated. The live installed-package test then starts from
a disposable repository and asks Codex to bypass dev-flow and directly modify a sentinel file under an
`/l5` goal. It must prove both:

1. without admission, the sentinel, Git refs/worktrees, dispatcher log, and provider/model counters are
   unchanged; and
2. with the canonical marker and sealed campaign fixture, direct depth-0 mutation remains blocked while
   exactly one managed implementer invocation is admitted.

Run the same prompt against a deliberately broken/absent hook adapter; the fixture must go red, proving
the positive result is not a model-compliance accident. Commit the sanitized receipt and update
portability/docs/CHANGELOG claims from that receipt only.

**Done when:** the real Codex negative, positive, and broken controls are reproducible, all counters and
Git state match the contract, and no other platform package or workflow changed behavior.

The live test must print `SKIP` when the explicit opt-in is absent and must fail—not skip—when opt-in is
present but Codex, plugin installation, a required hook event, or a denial control is unavailable.

Review is change-only. The implementation reviewer receives the accepted plan/rubric and the exact
candidate diff. Maximum two repair generations per deliverable; a repeated blocker ends the deliverable
instead of creating another phase, branch, ticket, or model lineage.

## 6. Risks + inversion

| What would guarantee failure | Mitigation / oracle |
|---|---|
| Treating an unavailable `TaskCreate` as permission to write Markdown work orders | Codex adapter explicitly forbids substitution; live adversarial transcript and zero-effect sentinels are required. |
| Adding a second lifecycle receipt or tracker | D3 consumes only `session-mode` and existing Mission/campaign digests; rubric rejects any parallel authority. |
| Checking the marker after readiness, branch, worktree, or model effects | Downstream seams are counter-stubbed; every invalid case must report all-zero counters. |
| Claiming Codex blocking semantics from docs or probe telemetry alone | D1 requires a real binary allow/deny/broken-control receipt before production wiring. |
| Regex parsing arbitrary shell/JavaScript tool input | Forbidden by the dependency decision; scope only to live-proven exact tool boundaries. |
| Making Claude/OpenCode/Grok/Kimi pay for the Codex gap | Canonical bodies and non-Codex adapters stay unchanged; shared core only tightens a precondition normal front doors already satisfy. |
| Letting tests/reviews become more execution phases | Four-row ceiling is mechanically asserted in the implementation campaign graph; retries remain inside their row. |
| A green live test caused by model obedience rather than enforcement | The same prompt must fail under the broken-hook control, and state counters—not prose—decide the verdict. |
| Allowing marker expiry/corruption to fail open | Codex production adapter and managed engine validator use the strict loader; explicit negative fixtures cover every invalid class. |

## 7. Out of scope

- Rewriting all canonical skills into a new host-neutral DSL.
- Providing Claude's `TaskCreate`, `TaskUpdate`, `TaskStop`, or native `Agent` APIs inside Codex.
- A general-purpose shell/JavaScript side-effect classifier.
- Enabling every Claude hook in the Codex package or claiming full-plugin parity.
- Changing Mission graph, campaign contract, work-order, task-status, or closeout schemas beyond consuming
  their existing digests at the managed-entry boundary.
- Changing Grok/Kimi/GLM/MiniMax/Gemini leaf-runner prompts or allowing them to act as depth-0 controllers.
- Reopening, repairing, merging, or cleaning the unrelated
  `fix/mission-campaign-authorized-creates` working-tree changes as part of this plan.
- Creating a project tracker or backlog row before this plan reaches terminal heterogeneous review.
