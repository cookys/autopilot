+| D2 | What else moves to the real main checkout? | **Only the placement.** `MAIN_CHECKOUT` for the fingerprint, `IDENTITY_REPO_ROOT`, the boundary checks and the `.autopilot-worktree` root keep using the caller's toplevel, as today. | Keeps this task from silently changing what the boundary protects. |
+| D3 | Fingerprint vs worktrees under `.claude/worktrees/` | `main_checkout_fingerprint` always prunes `$MAIN_CHECKOUT/.claude/worktrees` in the stat walk — the directory entry itself and everything under it. Pruning only this run's worktree would still trip on every concurrent rail and session (the existing false positive above). Trade-off stated for plan-review: an edit by a hand into a *sibling* worktree is no longer caught by this fingerprint (it never was for siblings in `/tmp`). |
+| D4 | Rail worktree names | Keep the prefixes: `hetero-<branch>-XXXXXX`, `foreman-<run_id>-XXXXXX`, `batch-integ-<run_id>-XXXXXX`, now under `<main>/.claude/worktrees/`. | Every basename matcher (`worktree-reap.sh:613`, registry, sweep) keeps working; the directory now says which repo. |
+| D5 | Marker for gap 6 | `set` and `set --new-task` re-resolve `repo_root` to the cwd's toplevel when its repo identity equals the marker's; `stage-advance` measures E1 in the cwd's toplevel when its identity equals the marker's, else in `marker.repo_root` as today. | The rail consumers compare `repo_root` to the caller's toplevel; following the session's worktree makes them match where the session works. Identity check keeps a cross-repo cwd from hijacking the marker. |
+| D6 | base_ref default (gap 6b) | Pairs in order `develop`/`origin/develop`, `main`/`origin/main`, `master`/`origin/master`. A ref qualifies only when it exists and has a merge-base with `HEAD` (today's filter, kept). The first pair with a qualifying member wins: both qualify → local is ancestor of remote ⇒ remote; remote ancestor of local ⇒ local; diverged ⇒ remote. One qualifies ⇒ that one. +# Worktree and handoff placement
+
+Where a repo's worktrees and handoff files go, who puts them there, and why the two handoff routes use
+different keys. One resolver answers every path question: [`scripts/resolve-repo-placement.js`](../scripts/resolve-repo-placement.js).
+Decisions and evidence: [`docs/plans/2026-10-12-worktree-placement.md`](../docs/plans/2026-10-12-worktree-placement.md).
+
+## The rule
+
+**Every worktree of a repo lives under one root: `<main checkout>/.claude/worktrees/`**, whoever creates it.
+The main checkout is the parent of the repo's `.git` directory (`git rev-parse --git-common-dir`), found the same
+way from the main checkout and from any linked worktree, so every worktree of one repo shares one root and the
+path says which repo it belongs to.
+
+| Who creates it | Name under `.claude/worktrees/` | How |
+|---|---|---|
+| A person, `claude -w <name>`, `EnterWorktree`, a subagent with `isolation: "worktree"` | `<name>` (subagents: `agent-<id>`); branch `worktree-<name>` unless created by hand | Claude Code's own placement; autopilot does not take it over (no `WorktreeCreate` hook) |
+| `dispatch-hetero.sh` | `hetero-<branch>-XXXXXX` | `resolve-repo-placement.js worktree --prefix hetero --slug <branch> --from <repo root>` |
+| `dispatch-foreman.sh` | `foreman-<run_id>-XXXXXX` | same, `--prefix foreman` |
+| `dispatch-batch.sh` (integration worktree) | `batch-integ-<run_id>-XXXXXX` | same, `--prefix batch-integ` |
+
+Claude Code's own behaviour here (names, branch, sweep, prompts, isolation) is from the docs and runs recorded in
+[`spike-native-worktree.md`](../docs/plans/evidence/2026-10-12-worktree-placement/spike-native-worktree.md); the
+refused `!` pull is gap 8 of [the backlog note](../docs/backlog/worktree-and-handoff-placement-has-no-rule.md).
+
+- **Name a hand-made worktree after its task**, and open a fresh one for the next task instead of branching a new
+  task inside the old one. `session-mode.js set --new-task` prints one advisory line when the worktree's directory
+  name and its branch share no word (generic words such as `feat`, `fix`, `wip` and digit-only words do not count).
+  It never blocks.
+- **Fallback**: a repo with no non-bare main checkout (a bare repo, a separate `--git-dir`) keeps rail worktrees in
+  the temp dir, and the resolver says so on stderr. The residue registry still lists those temp prefixes.
+- **Stay in the temp dir**: the `verify-red-green.sh` and test-integrity-L1 scratch worktrees. They are
+  short-lived, removed by their own script, and never handed to a person.
+
+### What follows from one root
+
+- Rail worktrees carry the `.autopilot-worktree` marker; liveness is the marker's lock, not a process cwd.
+  `repo-residue-sweep.js` skips a busy worktree under `.claude/worktrees/` only when it has no valid marker.
+- `orchestrator-edit-gate` treats a marked worktree under `.claude/worktrees/` as a dispatch worktree (depth-0
+  gated, subagents free), exactly as it treats one in the temp dir. An unmarked one is part of the repo's
+  `.claude/` tree, which the gate already allows.
+- The main-checkout boundary fingerprint skips `.claude/worktrees/`: each worktree there is another checkout with
+  its own review.
+- Repo-tree walkers that start at the main checkout (`identifier-scan.js`, `probe-unknown.js`,
+  `lib/worktree-activity.js`) skip `.claude/worktrees/`.
+- The rails add `/.claude/worktrees/` to the repo's shared `info/exclude`, so a consumer repo that does not ignore
+  that path sees no untracked entries. Its tracked `.gitignore` is not edited.
+- Claude Code's periodic worktree sweep only removes worktrees it created itself, so it never removes a rail
+  worktree there; `EnterWorktree` into `.claude/worktrees/` needs no prompt.
+
+## The session marker follows the session
+
+`session-mode.js set` (with or without `--new-task`) moves the marker's `repo_root` to the toplevel it runs in
+when that toplevel belongs to the same repo (same repo identity), and `stage-advance.js` measures the E1 diff in
+that worktree. A cwd in another repo leaves the marker alone. `base_ref` defaults to the newer of `develop` and
+`origin/develop` (then `main`, `master`), so a main checkout that has not pulled does not inflate E1.
+
+## Handoff files
+
+| Route | Path | Key | Consumed by |
+|---|---|---|---|
+| Active project | `<projects_dir>/<project>/HANDOFF.md` | the project (`resolve-project-paths.sh`) | whoever resumes the project |

+
+Ask for a path with `resolve-repo-placement.js handoff --route manual|clear [--from <dir>]`; the hooks call its
+`clearHandoffKey()`. The keys differ on purpose: the manual handoff is written for a person or a later session to
+find from anywhere in the repo, while the `/clear` handoff is injected automatically, and a per-repo key would let a
+parallel session in a sibling worktree consume it.
+
+## Bringing the main checkout up to date
+
+A Claude Code session isolated in a worktree (`--worktree`, `EnterWorktree`) cannot move the main checkout's
+branch: git refuses to update a branch checked out elsewhere, and the session's isolation refuses git commands
+aimed at the main checkout, including the owner's `!` commands typed into that session. After a push, the owner runs
+this from a terminal that is not the isolated session:
+
+```bash
+node <plugin>/scripts/resolve-repo-placement.js main --from <any worktree of the repo>
+# {"main_checkout": "...", "behind": N, ...}  — N commits behind its upstream
+git -C <main_checkout> pull --ff-only
+```
+

+#!/usr/bin/env node
+'use strict';
+
+// resolve-repo-placement.js — where a repo's worktrees and handoffs live (plan
+// docs/plans/2026-10-12-worktree-placement.md, D1/D8/D12; the rule: references/worktree-placement.md).
+// Node built-ins only: the rails call it on their dispatch path.
+//
+//   main     [--from <dir>]                         → JSON {main_checkout, repo_identity, fallback, behind}
+//   worktree --prefix <p> --slug <s> --from <dir>   → one line: a `mktemp -u -d` template
+//   handoff  --route manual|clear [--from <dir>]    → one line: the handoff file path
+//
+// main_checkout is the dirname of the absolute git common dir, accepted only when that basename is
+// `.git` and its parent is a non-bare work tree; otherwise fallback is true and main_checkout is
+// null (bare repo, separate --git-dir). `worktree` then answers a temp-dir template and says so on
+// stderr; on the normal path it runs `mkdir -p <main>/.claude/worktrees` first, so a rail that
+// calls it before its before-fingerprint never sees that directory appear as a mutation.
+// `worktree` requires --from: a rail passes its own repo root, never the process cwd.
+//
+// Handoff keys differ on purpose. manual: one file per repo, shared by its worktrees —
+// ~/.autopilot/handoff-manual/<basename>-<sha1(repo_identity)[0:8]>.md. clear: one per worktree —
+// ~/.autopilot/handoff/<sha1(realpath toplevel)>.md, consumed by the next session in that same
+// worktree (a per-repo key would let a parallel session in a sibling worktree consume it).
+//
+// Exit: 0 answer printed; 1 --from is not inside a git repo (worktree, handoff clear); 2 usage.
+
+const childProcess = require('child_process');
+const crypto = require('crypto');
+const fs = require('fs');
+const os = require('os');
+const path = require('path');
+
+function git(cwd, args) {
+  try {
+    return childProcess.execFileSync('git', args, { cwd, encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] }).trim();
+  } catch (_error) {
+    return null;
+  }
+}
+
+// Repo identity comes from project-key, loaded on first use: the hooks that only need clearHandoffKey
+// stay off its require graph.
+function repoIdentity(from) {
+  return require('../src/status/project-key').scopeFromCwd(from).repo_identity;
+}
+
+function realpathOr(dir) {
+  try { return fs.realpathSync(dir); } catch (_error) { return dir; }
+}
+
+function toplevel(from) {
+  const top = git(from, ['rev-parse', '--show-toplevel']);
+  return top ? realpathOr(top) : null;
+}
+
+function mainCheckout(from) {
+  const common = git(from, ['rev-parse', '--path-format=absolute', '--git-common-dir']);
+  if (!common) return null;
+  const commonReal = realpathOr(common);
+  if (path.basename(commonReal) !== '.git') return null;
+  const parent = path.dirname(commonReal);
+  if (git(parent, ['rev-parse', '--is-bare-repository']) !== 'false') return null;
+  if (git(parent, ['rev-parse', '--is-inside-work-tree']) !== 'true') return null;
+  return toplevel(parent) === parent ? parent : null;
+}
+
+function behindUpstream(dir) {
+  const count = git(dir, ['rev-list', '--count', 'HEAD..@{upstream}']);
+  return count !== null && /^\d+$/.test(count) ? Number(count) : null;
+}
+
+function resolveMain(from) {
+  const main = mainCheckout(from);
+  return {
+    main_checkout: main,
+    repo_identity: repoIdentity(from),
+    fallback: main === null,
+    behind: main === null ? null : behindUpstream(main),
+  };
+}
+
+function worktreeTemplate(from, prefix, slug) {
+  const name = `${prefix}-${slug.replace(/\//g, '-')}-XXXXXX`;
+  const main = mainCheckout(from);
+  if (main === null) return { template: path.join(os.tmpdir(), name), fallback: true };
+  fs.mkdirSync(path.join(main, '.claude', 'worktrees'), { recursive: true });
+  return { template: path.join(main, '.claude', 'worktrees', name), fallback: false };
+}
+
+function sha1(text) {
+  return crypto.createHash('sha1').update(text).digest('hex');
+}
+
+// The /clear key: sha1 of the realpath toplevel. hooks/session-handoff.js and session-start.js call
+// this instead of hashing on their own.
+function clearHandoffKey(repoRoot) {
+  return sha1(repoRoot);
+}
+
+function handoffPath(from, route, homeDir = os.homedir()) {
+  if (route === 'clear') {
+    const top = toplevel(from);
+    return top ? path.join(homeDir, '.autopilot', 'handoff', `${clearHandoffKey(top)}.md`) : null;
+  }
+  const identity = repoIdentity(from);
+  if (!identity) {
+    const cwd = realpathOr(from);
+    return path.join(homeDir, '.autopilot', 'handoff-manual', `${path.basename(cwd)}-${sha1(cwd).slice(0, 8)}.md`);
+  }
+  return path.join(homeDir, '.autopilot', 'handoff-manual', `${repoName(from)}-${sha1(identity).slice(0, 8)}.md`);
+}
+
+// The repo's name, the same from every worktree: the main checkout's basename, or for a bare repo
+// (no main checkout) the common dir's basename without `.git`.
+function repoName(from) {
+  const common = realpathOr(git(from, ['rev-parse', '--path-format=absolute', '--git-common-dir']) || from);
+  const base = path.basename(common);
+  if (base === '.git') return path.basename(path.dirname(common));
+  return base.replace(/\.git$/, '') || base;
+}

+const USAGE = 'usage: resolve-repo-placement.js main [--from <dir>]\n'
+  + '       resolve-repo-placement.js worktree --prefix <p> --slug <s> --from <dir>\n'
+  + '       resolve-repo-placement.js handoff --route manual|clear [--from <dir>]\n';
+
+function parseArgs(argv) {
+  const opts = {};
+  for (let i = 0; i < argv.length; i += 2) {
+    const key = argv[i];
+    const value = argv[i + 1];
+    if (!/^--(from|prefix|slug|route)$/.test(key || '') || value === undefined || value === '') return null;
+    opts[key.slice(2)] = value;
+  }
+  return opts;
+}
+
+function main(argv) {
+  const [command, ...rest] = argv;
+  if (command === '--help' || command === '-h') {

+    return 0;
+  }
+  const opts = parseArgs(rest);
+  if (!opts || !['main', 'worktree', 'handoff'].includes(command)) {

+    return 2;
+  }
+  const from = path.resolve(opts.from || process.cwd());
+  if (command === 'main') {

+    return 0;
+  }
+  if (command === 'worktree') {

+      process.stderr.write(USAGE);

+    }
+    if (!toplevel(from)) {
+      process.stderr.write(`resolve-repo-placement: not inside a git repo: ${from}\n`);
+      return 1;
+    }
+    const answer = worktreeTemplate(from, opts.prefix, opts.slug);
+    if (answer.fallback) {
+      process.stderr.write('resolve-repo-placement: no non-bare main checkout; worktree stays in the temp dir\n');
+    }
+    process.stdout.write(`${answer.template}\n`);
+    return 0;
+  }
+  if (opts.route !== 'manual' && opts.route !== 'clear') {
+    process.stderr.write(USAGE);
+    return 2;
+  }
+  const answer = handoffPath(from, opts.route);
+  if (answer === null) {
+    process.stderr.write(`resolve-repo-placement: not inside a git repo: ${from}\n`);
+    return 1;
+  }
+  process.stdout.write(`${answer}\n`);
+  return 0;
+}
